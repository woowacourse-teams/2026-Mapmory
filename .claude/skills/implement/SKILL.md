이슈 #$ARGUMENTS 를 구현한다.

## 1. 계획 (아직 코드를 고치지 않는다)

1. `gh issue view $ARGUMENTS`로 이슈를 읽는다. "정한 것", "정하지 않은 것", "완료 조건"을 확인한다.
2. 관련 코드, 테스트, `backend/docs/adr/`, `.github/claude-review/domain.md`에서 이 변경이 닿는 절을 읽는다.
3. 계획을 보여 준다.
   - 이 변경이 지켜야 할 불변식 한두 줄
   - 바꿀 파일과 방법, 추가할 테스트(버그면 고치기 전 코드에서 실패할 테스트)
   - **제안:** 이슈의 "정하지 않은 것", 또는 범위·API 계약·도메인 정책·잠금 순서처럼 새로 정해야 하는 것. 항목마다 선택지 2~3개와 근거, 추천을 쓴다.
4. 여기서 멈추고 승인을 기다린다. 제안이 없어도 계획은 승인받는다.

## 2. 구현

- 승인된 계획과 이슈의 "정한 것"만 따른다. 구현 중에 새로 정해야 할 것이 생기면 다시 멈추고 제안한다.
- 버그는 실패하는 테스트를 먼저 쓰고 실패를 확인한 뒤 고친다.
- `backend/CLAUDE.md`의 확인 명령으로 관련 테스트를 돌린다. 마지막에 `./gradlew clean build`를 한 번 돌린다.

## 3. 마무리

- 실행한 명령과 결과(통과·실패 수, 버그면 고치기 전 실패 출력)를 보여 준다.
- `.github/pull_request_template.md` 형식으로 PR 설명 초안을 쓴다.
  - **내가 정한 것:** 이슈의 "정한 것"
  - **AI 제안을 받아들인 것:** 1단계에서 사람이 승인한 제안
  - **AI가 정한 어떻게:** 그 밖의 구현 선택
  - **확인 증거:** 위 명령과 결과
- 커밋과 PR 생성은 사람이 하라고 할 때만 한다.
