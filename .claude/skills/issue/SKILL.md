다음 내용으로 GitHub 이슈 초안을 만든다: $ARGUMENTS

무엇·왜는 사람이 정한다. 이 스킬은 사람이 정하도록 돕는 것이지, 대신 정하는 것이 아니다.

1. 기능이면 `.github/ISSUE_TEMPLATE/기능-개발-템플릿.md`, 버그면 `.github/ISSUE_TEMPLATE/버그-수정-템플릿.md`를 읽는다.
2. 관련 코드와 `backend/docs/adr/`, `.github/claude-review/domain.md`·`policies.md`에서 이 일이 닿는 흐름과 이미 정해진 결정을 찾는다. 이미 정해진 것은 묻지 않고 "정한 것"에 근거와 함께 채운다.
3. 템플릿의 빈칸을 채우는 데 필요한 것만 질문한다. 한 번에 2~4개씩, 가능하면 선택지를 붙인다.
   - 기대 동작과 API 계약(상태 코드, 응답 형태), 범위에 넣지 않을 것, 동시에 오거나 두 번 오면 어떻게 끝나야 하는지
   - 사람이 "모르겠다", "나중에"라고 답하면 그 항목은 "정하지 않은 것"으로 둔다. 대신 정하지 않는다.
4. 완료 조건은 통과·실패로 확인할 수 있게 쓴다(실행할 테스트, 재현 시나리오). "잘 동작한다" 같은 말은 쓰지 않는다.
5. 초안을 보여 주고 고칠 곳을 묻는다. 사람이 올리라고 하면 그때 `gh issue create`로 올린다. 묻지 않고 올리지 않는다.
