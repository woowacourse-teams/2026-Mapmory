# ADR 0004. 지역 코드 체계와 계층 판단 방식

- 상태: 채택
- 날짜: 2026-08-10
- 관련: `V2__create_location.sql`, `V7__insert_location_province.sql`, `V8__insert_location_district.sql`, `V18__canonicalize_city_district_regions.sql`, `V19__restore_gwangju_jeonnam_district_codes.sql`

---

## 문제

지역을 어떤 코드로 저장할 것인가. 그리고 시·도와 시·군·구의 계층 관계를 무엇으로 판단할 것인가.

---

## 배경

### 코드 체계가 레벨마다 다르다

| 레벨 | 채택 체계 | 이유 |
|---|---|---|
| 국가 | ISO 3166-1 alpha-2 | 국제 표준, 지도 라이브러리 대부분이 사용 |
| 시·도 | ISO 3166-2 | 국제 표준, 명칭 변경에 영향받지 않음 |
| 시·군·구 | 행정표준코드 | ISO에 시·군·구 레벨이 없음 |

### 두 체계의 접두사가 일치하지 않는다

| 지역 | 시·도 (ISO 3166-2) | 시·군·구 (행정표준코드) |
|---|---|---|
| 세종 | **50** | 36110 |
| 제주 | **49** | 50110, 50130 |
| 강원 | **42** | 51xxx |
| 전북 | **45** | 52xxx |
| 광주·전남 | **29 / 46** | 광주 29xxx / 전남 46xxx |

**`50110 제주시`의 앞 두 자리 `50`은 ISO에서 세종특별자치시다.**
접두사로 상위 지역을 유추하면 제주시가 세종 소속이 된다.

### 행정구역 개편

- 2024년: 강원도 → 강원특별자치도, 전라북도 → 전북특별자치도
  → **ISO 코드는 변경되지 않았다.** ISO는 행정 단위의 지위가 아니라 지역 자체를 식별한다.
- 2026-07-01: 광주광역시 + 전라남도 → 전남광주통합특별시 출범
  → 구조 변경이며, ISO 3166-2는 아직 갱신되지 않은 것으로 보인다.

---

## 결정

### 1. 계층은 `parent_id`로만 판단한다

`region_code` 접두사로 상위 지역을 유추하는 로직을 **어떤 경우에도 작성하지 않는다.**

```sql
-- 금지
WHERE LEFT(region_code, 2) = :provinceCode

-- 사용
WHERE parent_id = :provinceId
```

### 2. 광주와 전남은 분리 유지한다

통합되었으나 지도 화면에서 두 지역이 **별개 도형으로 렌더링**되므로 데이터도 분리한다.
통합하면 사용자가 광주만 색칠할 수 없고 진행도 게이지가 화면과 어긋난다.

ISO 갱신 전이므로 기존 코드 `29`(광주) / `46`(전남)을 그대로 사용한다.
시·군·구도 클라이언트 지도와 동일하게 광주 `29xxx`, 전남 `46xxx` 기존 코드를 사용한다.
V8에서 선반영한 통합 코드 `12xxx`는 V19에서 기존 Region ID를 유지한 채 복원한다.

### 3. 시·도 `location.id`를 1~17로 고정한다

`V8`이 `parent_id`로 참조해야 하므로 명시적으로 지정한다.
국가는 `SET @kr := (SELECT id FROM country WHERE code='KR')`로 조회하여 country의 id 값에 의존하지 않는다.

---

## 검토한 대안

| 대안 | 기각 사유 |
|---|---|
| 시·군·구도 ISO로 통일 | ISO 3166-2에 시·군·구 레벨이 존재하지 않음 |
| 시·도도 행정표준코드로 통일 | 세계 지도 확장 시 국가는 ISO를 쓰므로 체계가 다시 갈림 |
| 접두사로 계층 유추 | 위 표대로 오매핑 발생 |
| 광주·전남 통합 1건 | 화면 도형과 불일치, 광주 단독 선택 불가 |

---

## 결과

- 코드 체계 불일치가 코드 레벨에서 문제를 일으키지 않는다.
- 행정구역이 다시 개편되어도 데이터만 추가하면 된다.
- 대신 **접두사 유추 금지를 팀이 계속 인지해야 한다.** `V2__create_location.sql` 상단 주석에 명시했다.

### 2026-08-28 보완 결정

서비스의 대한민국 여행 기록 단위를 다음과 같이 고정한다.

- 서울·광역시: 자치구·군
- 세종: 세종시
- 제주: 제주시·서귀포시
- 일반 도: 시·군

일반 도의 시 산하 일반구는 별도 여행 기록 Region으로 사용하지 않는다.
V18에서 39개 일반구 Region을 13개 canonical 시 Region으로 통합하고 기존 여행 기록도 시 Region으로 이관한다.
Region 타입은 기존 3단계 계층을 유지하기 위해 시와 구 모두 `DISTRICT`를 사용한다.

### 2026-09-15 보완 결정

클라이언트와 DB의 광주·전남 시군구 코드를 일치시킨다.

- 광주광역시: `29110`~`29200`의 기존 코드 사용
- 전라남도: `46110`~`46910`의 기존 코드 사용
- V8의 `12xxx` Region은 삭제·재생성하지 않고 V19에서 `region_code`만 갱신하여 기존 여행 기록 참조를 보존

---

## 미해결 사항

- **표시 명칭**: 통합 이후 사용자에게 `광주광역시` / `전라남도`로 보일지, 다른 명칭을 쓸지 기획 확정 필요.
- **지도 리소스 대조**: 안드로이드가 네이티브로 지도를 렌더링하므로, SVG/GeoJSON의 지역 식별자와 최종 canonical `region_code`를 계속 대조해야 한다. 일반 도의 일반구 경계는 클라이언트에서 시 단위로 병합한다.
