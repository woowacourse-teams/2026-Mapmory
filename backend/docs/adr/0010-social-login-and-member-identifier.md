# ADR 0010. 소셜 로그인은 앱이 전달한 카카오 토큰을 검증하고, 회원 식별자를 분리한다

- 상태: 채택
- 날짜: 2026-08-14
- 관련: #46, ADR 0009

---

## 문제

첫 로그인 수단으로 카카오를 지원한다. 클라이언트는 안드로이드/iOS 네이티브 앱이며,
카카오 SDK로 로그인할 수 있다. 백엔드는 이 로그인을 어떻게 검증하고, 회원을
어떻게 식별·저장할지 정해야 한다.

## 결정

### 앱이 전달한 카카오 access token을 백엔드가 검증한다

- 앱이 카카오 SDK로 로그인해 얻은 access token을 `POST /api/v1/auth/login/kakao`로 보낸다.
- 백엔드는 그 토큰으로 카카오 `GET /v2/user/me`를 호출해 회원번호와 닉네임을 얻는다.
- 카카오가 4xx/5xx를 반환하면(토큰 만료·위조) `INVALID_KAKAO_TOKEN`으로 처리한다.

### 회원 식별자를 용도별로 분리한다

- **내부 식별**: `Member`의 Long PK. JWT `sub`와 서버 내부 조회에 사용한다.
- **소셜 식별**: `(provider, provider_id)` 유니크. 카카오 회원번호로 find-or-create 한다.
- 닉네임만 사용한다(민감 동의항목 미사용). 미제공 시 기본값으로 채운다.

### uuid는 공개 식별자로 유지하되, 지금은 노출하지 않는다

`Member.uuid`는 "회원을 외부에 노출할 때 쓰는 공개 식별자"다. 순차 PK 노출을
막기 위한 것으로, 타인 조회·공유 같은 기능이 생기면 그때 URL·응답에 사용한다.
현재는 그런 기능이 없으므로 **로그인 응답에 회원 식별자를 노출하지 않는다.**
응답은 `accessToken`과 `isNewMember`만 반환하고, 클라이언트는 토큰만 저장한다.

## 검토한 대안

### 인가 코드(authorization code)를 백엔드가 교환

채택하지 않았다(당장). client secret을 서버가 보관해 더 안전하지만, 앱 SDK가
카카오톡 앱 연동을 매끄럽게 처리하고 구현이 단순하다. 보안 요구가 커지면 재검토한다.

### OIDC ID token 검증

채택하지 않았다(당장). 카카오 API 호출 없이 JWKS로 서명만 검증할 수 있으나,
카카오 콘솔에서 OpenID Connect 활성화가 선행되어야 한다.

### uuid를 제거하고 Long PK로 단일화

보류. 코드가 단순해지지만, 순차 PK가 외부에 노출된다. 타인 조회·공유가
로드맵에 있어 공개 식별자가 필요해질 수 있다. 나중에 `UUID()`로 backfill 하는 것도
가능하나 제거→재도입은 왕복 낭비이므로, 비용이 거의 없는 현 컬럼을 유지한다.

## 결과

### 장점

- 네이티브 앱 로그인 흐름에 맞고 구현이 단순하다.
- 소셜 계정과 내부 PK가 분리되어, 다른 소셜 제공자를 추가하기 쉽다.
- 회원 식별자 노출 정책을 처음부터 통제한다(공개 시 uuid, 내부는 Long).

### 비용과 주의점

- 이메일 등 민감 동의항목이 필요해지면 카카오 비즈니스 앱 검수가 선행되어야 한다.
- `uuid`는 현재 읽히지 않으므로, 죽은 코드로 오해하지 않도록 용도를 문서로 남긴다.
- refresh token 발급·회전은 별도 결정으로 다룬다(후속).
