# ADR 0011. refresh 토큰은 해시 저장·회전·폐기하고, 재사용을 감지한다

- 상태: 채택
- 날짜: 2026-08-14
- 관련: #47, ADR 0009

---

## 문제

access token은 단기(30분)라 자주 만료된다. 사용자가 매번 카카오 로그인을 다시 하지 않도록
장기 세션 수단이 필요하다. 동시에, 장기 토큰은 탈취 시 위험이 크므로 서버가 이를
폐기·회전할 수 있어야 한다.

## 결정

### refresh 토큰의 원문은 클라이언트에만, 서버는 해시만 저장한다

- 원문은 `SecureRandom` 32바이트를 Base64URL로 인코딩한 불투명 문자열이다.
- 서버는 원문을 저장하지 않고 **SHA-256 해시(64 hex)만** DB에 보관한다.
  DB가 유출되어도 저장된 해시로는 원문을 만들 수 없다.
- 조회는 들어온 원문을 같은 방식으로 해시해 대조한다.

### 사용 시 회전(rotation)한다

`POST /api/v1/auth/token/refresh`로 재발급할 때, 기존 refresh를 폐기(`revoked_at` 기록)하고
새 access/refresh 쌍을 발급한다. 하나의 refresh는 한 번만 유효하다.

### 서버가 폐기할 수 있다

`POST /api/v1/auth/logout`으로 refresh를 폐기한다. 만료·폐기·위조된 refresh로 재발급을
시도하면 401로 응답한다.

> 2026-10-25 구현 업데이트(#462): 로그아웃도 회전처럼 토큰 행을 잠그고 읽는다. 잠그지 않으면 재발급과 겹칠 때
> 회전이 커밋한 후속 토큰 연결(`replaced_by_id`)을 읽기 전 값으로 덮어써, 회전으로 나간 후속 토큰이 로그아웃 뒤에도 남았다.
> 이미 회전된 토큰으로 로그아웃하면 바로 다음 토큰까지 폐기한다. 체인을 끝까지 따라가면 오래된 토큰일수록 잠금이
> 회전 횟수만큼 쌓이므로 한 단계만 본다. 두 단계 이상 이전 토큰으로 로그아웃하면 그 세션의 최신 토큰은 남는다(#467).
> 반대로 로그아웃이 먼저 커밋되고 같은 토큰으로 재발급하면, 폐기된 토큰의 재사용이라 지금처럼 탈취로 처리된다.
> → #579 이후로는 탈취로 보지 않고 `401 INVALID_REFRESH_TOKEN`만 준다(아래 2026-11-03 구현 업데이트).

### 회전은 원자적으로 처리하고, 재사용은 탈취로 간주해 대응한다

같은 토큰으로 동시 요청이 와도 한 번만 회전되도록, 검증 시 토큰 행에 비관적 락
(`SELECT ... FOR UPDATE`)을 건다. 이미 폐기된 refresh가 다시 제시되면 정상 사용자와
탈취자가 같은 원문을 나눠 가진 상황이므로 해당 회원의 유효한 refresh를 **모두 폐기**한다.

이 일괄 폐기는 검증과 **같은 트랜잭션**에서 수행하고, 재사용일 때는 예외를 던지지 않고
결과로 신호한다(`Optional.empty`). 401 변환은 트랜잭션 밖(호출부)에서 하므로 폐기가
롤백되지 않는다. 게스트의 회전 응답 유실은 예외로 재발급한다(ADR 0023). (초기엔 `REQUIRES_NEW` 별도 트랜잭션을 썼으나, 비관적 락과 결합 시
같은 회원 행을 두 트랜잭션이 서로 기다리는 **데드락**이 생겨 같은 트랜잭션 방식으로 바꿨다.)

> 2026-11-03 구현 업데이트(#579): 재사용(탈취) 판정은 `replaced_by_id`가 있는 토큰, 즉 회전으로 폐기된 토큰에만 한다.
> 로그아웃·일괄 폐기(승격·버림·탈퇴)로 폐기된 토큰은 `401 INVALID_REFRESH_TOKEN`만 주고 회원의 다른 토큰은 건드리지 않는다.
> 같은 토큰을 가진 사람이 둘이라는 신호가 아니기 때문이다. 자세한 이유는 ADR 0023의 2026-11-03 구현 업데이트를 참조한다.

> 2026-11-04 구현 업데이트(#467): refresh 토큰을 세션(`refresh_token_family`)으로 묶는다. 로그인할 때 세션을 열고, 회전·게스트 응답 유실 재발급은
> 이전 토큰의 세션을 물려받는다.
> - 로그아웃은 제시된 토큰이 속한 세션의 유효한 토큰을 모두 폐기한다. 어느 시점의 토큰으로 로그아웃해도 그 세션에 쓸 수 있는 토큰이 남지 않고,
>   체인을 따라가지 않아 쿼리 수가 회전 횟수와 무관하다. 위 2026-10-25 업데이트의 "한 단계만 본다"와 "최신 토큰은 남는다"는 더는 맞지 않는다.
> - 재사용(탈취)으로 판정하면 회원 전체가 아니라 **그 세션의 토큰만** 폐기한다. 탈취자가 가진 것은 그 세션의 토큰뿐이므로 다른 기기의 세션은 끊지 않는다.
> - 승격·버림·탈퇴는 지금처럼 회원의 토큰을 모두 폐기한다.
> - 회전·로그아웃은 세션 행을 먼저 잠가 같은 세션의 작업을 직렬화한다(ADR 0028).

만료는 14일(`jwt.refresh-token-validity`)로 둔다.

## 검토한 대안

### refresh도 stateless JWT로 발급

채택하지 않았다. 구현은 단순하지만 서버가 특정 refresh를 폐기할 수 없어,
로그아웃·탈취 대응이 불가능하다. 폐기 가능성이 이 결정의 핵심 목적이다.

## 결과

### 장점

- 재로그인 없이 세션을 유지하면서, 서버가 언제든 refresh를 폐기할 수 있다.
- 원문을 저장하지 않아 DB 유출 시 토큰이 그대로 노출되지 않는다.
- 회전 + 재사용 감지로 탈취된 토큰의 수명을 제한한다.

### 비용과 주의점

- 매 재발급마다 DB 조회·쓰기가 발생한다(무상태 access와 달리 상태를 가짐).
- 만료·폐기된 토큰 정리(purge) 배치는 후속 과제다.
- 회전 검증이 비관적 락을 쓰므로, 같은 토큰에 동시 요청이 몰리면 잠깐 직렬화된다.
