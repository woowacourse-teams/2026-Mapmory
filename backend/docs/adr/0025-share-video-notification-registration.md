# ADR 0025. 영상 알림은 기존 푸시 등록 구조를 재사용하고 설치본 식별은 후속 개선한다

- 상태: 제안 (기존 엔티티 유지·요청 기기 대상·Outbox 적용은 사용자와 합의, 기기 등록 API는 로컬 구현·검증 완료)
- 날짜: 2026-10-29
- 관련: #545, #553, ADR 0022

## 문제

영상 생성은 서버 워커에서 계속되지만 앱이 백그라운드이거나 종료되었을 때 완료를 알릴 경로가 없다.
이미 앨범 알림용 `PushToken`, 등록·삭제 API, `PushSender`가 존재한다.
현재 FCM 토큰은 소유 회원과 플랫폼에 연결되고 별도 설치본 ID나 로그인 연결 세대는 없다.

처음부터 설치 UUID·활성 상태·연결 버전을 추가하는 설계를 검토했으나,
이번에는 기존 엔티티 구조를 유지하고 변경 필요성을 별도 리팩토링 이슈에 남기기로 했다.

## 결정

1. `PushToken`과 `push_token` 스키마를 변경하지 않는다. 기존 기능을 재사용한다.
2. 영상 요청 기기만 대상으로 삼는다. 등록 행 ID와 요청 당시 회원을 수신 대상의 기준으로 사용한다.
3. 로그아웃 전 기기 등록 해제가 성공하면 해당 행을 삭제한다. 재등록 시 새 PK를 발급받는다.
4. 계정 전환 시 기존 행의 회원만 변경하는 대신 삭제 후 새 행을 생성하는 서비스 변경을 제안한다.
   같은 회원·같은 토큰의 단순 재등록은 ID를 유지한다.
5. 발송 시 과거 ID가 없거나 소유 회원이 달라졌다면 생략한다. 다른 등록에 과거 알림을 자동 이전하지 않는다.
6. 영상 완료와 Outbox 이벤트를 같은 트랜잭션에 저장한다. 외부 FCM 호출은 커밋 이후 별도 워커에서 수행한다.
7. 앨범의 메모리 이벤트 방식을 영상 알림의 내구성 보장으로 사용하지 않는다. 앨범 알림의 Outbox 전환은 이번 결정 범위 밖이다.
8. 설치본 식별·로그인 연결 세대·토큰 갱신 추적은 #553에서 검토한다.
9. 기기 등록은 TransactionTemplate 실행 범위 안에서 조회·잠금·삭제·저장을 수행하고, 실행 범위 밖에서 토큰 중복·잠금 충돌을 409로 변환하는 안으로 작성한다.
   REQUIRES_NEW로 등록 단위를 독립시킨다. 현재 Controller 직접 호출에는 REQUIRED도 가능하지만 호출 경로가 바뀌어도 커밋 경계를 유지하려는 선택이다.
10. 등록 응답으로 행 ID를 반환하고 해제는 회원 ID와 등록 ID를 함께 조건으로 사용한다.

## 트랜잭션과 등록 ID 선택의 근거

- 계정 전환의 삭제와 새 저장은 원자적으로 처리해야 한다. DELETE 후 flush는 실행 순서를 보장하기 위한 것이며 커밋이 아니다.
- UNIQUE 위반은 실행·flush뿐 아니라 커밋 시점에 드러날 수 있다. TransactionTemplate의 execute 전체를 감싸면 등록 단위 종료 후 예외를 분류할 수 있다.
- private 메서드에 @Transactional만 추가해 같은 객체에서 호출하지 않는다. template가 경계를 열고 private 메서드는 등록 로직만 수행한다.
- REQUIRES_NEW는 외부 작업의 롤백과 독립적이며 외부 트랜잭션이 있으면 커넥션을 추가로 요구할 수 있다. 독립 기기 등록에 한정하고 영상 완료·Outbox의 동일 트랜잭션 보장을 대체하지 않는다.
- token은 FCM 전달 주소이고 행 ID는 한 번 생성된 등록을 가리킨다. token 자체를 제거·대체하는 결정이 아니다.
- 예: 등록 42 해제가 서버에서 성공했지만 응답이 유실됨 → 같은 token으로 새 등록 43 생성 → 지연된 해제 재시도 도착. token+회원 삭제는 43도 지울 수 있지만 ID 42+회원 삭제는 43을 유지한다.
- 단, 첫 해제 자체가 실행되지 않아 같은 회원 재등록이 여전히 42를 사용하면 ID만으로 로그인 세대를 구분하지 못한다. 해제 성공 후 새 행 생성이라는 전제가 필요하다.
- API 예시·트랜잭션 흐름·선택하지 않은 대안은 [상세 설계](../share-video-notification.md)에 기록한다.

## 검토한 대안

- 설치 UUID와 연결 버전을 지금 추가: 토큰 갱신과 세션 경계가 명확해지지만, 이번 단계의 엔티티 유지 결정에 따라 후속 개선으로 분리한다.
- 토큰 문자열만 영상 작업에 저장: 같은 토큰 값의 재등록을 과거 연결과 구분하기 어려워 등록 행 ID를 사용한다.
- 완료 시 회원의 모든 토큰 조회: 요청 기기만 받는 정책에 맞지 않아 선택하지 않는다.
- 등록 행의 소유 회원만 변경: A→B→A 이후 과거 등록 ID가 다시 일치할 수 있어 계정 전환 시 새 행 생성안을 제안한다.

## 결과와 한계

- 기존 엔티티·DB 마이그레이션 없이 기기 등록을 활용할 수 있다. 새 응답 DTO와 서비스·API 변경은 별도로 필요하다.
- 토큰 갱신 후 같은 설치본의 새 주소로 과거 알림을 자동 연결하지 못한다.
- 로그아웃 요청과 기기 등록 해제가 분리되어 있어, 해제 실패 또는 요청 순서 역전 시 취소를 완전히 보장하지 못한다.
- FCM에 이미 접수한 메시지의 회수는 보장하지 않는다.
- 등록 API의 204→200 응답과 해제 요청 변경은 공개 계약 변경이다. 클라이언트와 전환 계획을 맞춘다.
- 작업·Outbox가 등록 행 삭제를 막거나 함께 삭제되지 않도록 다음 단계의 참조 정책을 결정해야 한다.
- 자세한 API·경쟁 조건·검증 항목은 [기기 등록 설계](../share-video-notification.md)에 기록한다.

## 구현 상태

이 ADR은 결정과 제안을 기록하며 구현 완료를 뜻하지 않는다.
기기 등록·해제 API와 서비스의 트랜잭션·충돌 처리를 로컬 코드에 반영했다.
2026-10-29에 `./gradlew test --tests 'com.mapmory.backend.notification.*'`를 실행해 관련 20개 테스트가 통과했다. 같은 토큰의 동시 최초 등록 2건과 외부 트랜잭션 롤백 후 독립 등록 유지도 확인했다.
영상 수신 대상 연결·Outbox·실제 FCM 발송과 클라이언트 연동은 아직 구현하지 않았다.
DB 스키마는 유지했고 이 작업에서 배포·커밋·푸시는 하지 않았다.
