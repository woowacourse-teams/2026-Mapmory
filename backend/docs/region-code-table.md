# 대한민국 여행 기록 지역 코드표

> 기준일: 2026-09-15
> 적용 상태: `V19__restore_gwangju_jeonnam_district_codes.sql` 반영 완료

## 1. 목적

이 문서는 대한민국 여행 기록에서 사용하는 canonical 지역 단위와 코드를 정의한다.
행정 원본 데이터가 더 세분되어 있더라도 서비스의 선택·저장·조회·지도 집계는 이 문서의 단위를 따른다.

## 2. 지역 선택 단위

| 상위 지역 | 여행 기록 단위 | 예시 |
| --- | --- | --- |
| 서울특별시 | 자치구 | `11680 강남구` |
| 광역시 | 자치구·군 | `26350 해운대구`, `26710 기장군` |
| 세종특별자치시 | 세종시 | `36110 세종시` |
| 제주특별자치도 | 행정시 | `50110 제주시`, `50130 서귀포시` |
| 일반 도 | 시·군 | `41110 수원시`, `41820 가평군` |

일반 도에 속한 시의 일반구는 여행 기록 단위로 사용하지 않는다.
예를 들어 `수원시 권선구`가 아니라 `수원시`를 선택하고 저장한다.

`시·도 코드`는 API의 `provinceCode`, `canonical 코드`는 `districtCode`에 사용한다.
Region 모델에는 별도 `CITY` 타입이 없으므로 위 13개 시도 `DISTRICT`로 저장한다.

## 4. 요청 예시

수원시 여행 기록은 일반구와 무관하게 다음 경로를 사용한다.

```json
{
  "countryCode": "KR",
  "provinceCode": "41",
  "districtCode": "41110"
}
```

다음 요청은 여행 기록 저장용 코드로 사용하지 않는다.

```json
{
  "countryCode": "KR",
  "provinceCode": "41",
  "districtCode": "41113"
}
```

## 5. 신규 행정구역 반영 규칙

1. 특별시·광역시의 자치구·군은 개별 여행 기록 지역으로 추가한다.
2. 일반 도의 시·군은 개별 여행 기록 지역으로 추가한다.
3. 일반 시에 일반구가 신설되거나 변경되어도 일반구 코드는 여행 기록 Region에 추가하지 않는다.
4. 일반구 경계가 필요하면 클라이언트 지도 원본 또는 별도 행정 데이터로만 관리하고, 여행 기록 코드는 시 단위로 통합한다.
5. 코드 추가·변경 시 클라이언트 지도 코드, 백엔드 Region 데이터, API 테스트를 함께 대조한다.
6. `region_code` 접두사로 상위 지역을 추론하지 않고 `parent_id`로 계층을 확인한다.

광주광역시와 전라남도는 통합 행정구역 코드를 선반영하지 않는다. 클라이언트 지도와 동일하게 광주는 `29xxx`, 전남은 `46xxx` 시군구 코드를 사용하며, V8의 `12xxx` 코드는 V19에서 복원했다.

## 6. 폐기 코드 관리

위 표의 일반구 코드는 V18 마이그레이션에서 Region 저장 데이터에서 제거한다.
이 문서에는 다음 목적으로 계속 보존한다.

- 기존 데이터 이관 시 `일반구 코드 → canonical 시 코드` 매핑
- 행정구역 변경 이력 확인
- 같은 일반구 코드가 다시 여행 기록 단위로 추가되는 것 방지

Markdown 문서는 정책 설명과 변경 이력을 위한 자료다. 실제 허용 코드는 DB 마이그레이션과 자동화 테스트로 함께 보장해야 한다.
