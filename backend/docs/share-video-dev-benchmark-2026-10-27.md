# 공유 영상 개발 환경 측정 (2026-10-27)

## 목적과 환경

- 대상: `https://dev-api.map-mory.com/`의 개발 API와 개발 렌더러 1대 (`t4g.small`, 영상 작업 동시 처리 1개).
- 목적: 국가 수에 따른 사용자의 영상 준비 대기 시간과 파일 크기, 동시 요청 시 대기 시간을 관찰한다.
- 합성 여행 기록만 사용했다. 운영 API와 실제 사용자 데이터는 사용하지 않았다.
- 이 측정은 클라이언트에서 관찰한 시간이다. 렌더러 프로세스만의 실행 시간이나 운영 환경의 성능을 뜻하지 않는다.

## 입력 시나리오

1. 사례별로 개발 API의 `POST /api/v1/auth/login/guest`를 호출해 별도의 임시 게스트 계정과 인증 토큰을 발급받았다.
2. 각 계정에 `POST /api/v1/travel-records`로 **국가당 여행 기록 1개**를 만들었다. 제목은 `Video timing benchmark <사례> <국가 코드>`, 내용은 `Synthetic benchmark record`, 시작일과 종료일은 2025년 각 월 1일과 2일로 지정했다. 사진 첨부와 태그는 비웠다.
3. 단독 요청에는 아래 국가 목록의 앞 2개, 5개, 또는 10개를 사용했다.

| 국가 수 | 국가 코드 |
| --- | --- |
| 2 | JP, GB |
| 5 | JP, GB, FR, US, IT |
| 10 (성공 사례) | JP, GB, FR, US, IT, DE, CA, AU, ES, NL |

4. 단독 사례는 동일한 계정의 같은 기록으로 영상을 2번씩 생성했다. 즉, 두 번째 반복에서 기록을 추가하지 않았다.
5. 동시 요청은 5개국 기록을 가진 **서로 다른 게스트 계정 3개**를 준비하고, 실행 장벽을 이용해 요청을 거의 같은 시점에 보냈다. 본 측정 전에 5개국 단독 사전 확인 1회를 수행했다.

요청 순서는 다음과 같다. 인증 토큰과 서명된 다운로드 URL은 결과 파일이나 문서에 기록하지 않았다.

```text
POST /api/v1/auth/login/guest              → 임시 게스트 토큰
POST /api/v1/travel-records                 → 국가별 합성 기록 생성
POST /api/v1/share-videos/travel-timeline   → jobId 수신
GET  /api/v1/share-videos/{jobId}           → 2초 간격으로 COMPLETED/FAILED 확인
GET  /api/v1/share-videos/{jobId}/download-url
GET  <발급된 HTTPS 다운로드 URL>              → MP4 내려받기
```

## 측정 방법

- 영상 생성 요청 직전부터 `COMPLETED`를 처음 관찰할 때까지 `time.monotonic()`으로 잰 값을 **요청→준비 완료 시간**으로 기록했다. API 호출·큐 대기·렌더링·업로드·상태 조회 지연이 모두 포함된다. 2초 간격 조회 때문에 완료 시각에는 약 2초의 조회 간격과 네트워크 지연만큼 관측 오차가 생길 수 있다.
- `RENDERING`을 처음 관찰한 시간도 별도로 기록했다. 이는 상태 조회 결과일 뿐, 서버의 정확한 렌더 시작 시각이나 **순수 렌더링 소요 시간**이 아니다.
- `COMPLETED` 후 발급받은 URL로 MP4를 내려받아 바이트 수로 파일 크기를 기록했다. 다운로드 소요 시간은 요청→준비 완료 시간에 넣지 않았다.
- 성공 파일의 MP4 헤더와 재생 길이를 확인했다. 측정 파일은 로컬 임시 폴더에 저장했다.
- 아래 MB는 `1 MB = 1,000,000 bytes`이다.

## 실패와 측정 중단

- 최초 10개국 사례에는 마지막 국가로 `SG`를 사용했다. 작업 15가 약 6.516초 후 `FAILED`가 됐다. 당시 배포된 렌더러의 국가 좌표 목록에 `SG`가 없는 것을 확인했으므로 이 누락이 **유력한 원인**이다. 렌더러의 실제 실패 로그로 확정하지는 못했다.
- `SG`를 `NL`로 바꿔 요청한 작업 16을 관찰하던 중 개발 API가 일시적으로 HTTP 502를 반환해 측정이 중단됐다. 이후 API가 복구되어 5개국 동시 요청과 10개국 단독 요청을 끝냈다. 작업 16의 최종 상태는 확인하지 못했다.
- 502 시점에 개발 API의 별도 배포가 진행됐다. 두 사건의 시간대가 겹치지만, 원인을 확정할 자료는 없다.
- 테스트로 임시 게스트 계정 8개, 합성 여행 기록 52개, 영상 작업 12개가 개발 환경에 생성됐다. 이 작업에서는 데이터를 삭제하지 않았다.

## 해석과 다음 확인

- 파일 크기와 대기 시간은 국가 수가 늘면서 증가했다. 기록당 사진은 넣지 않았으므로 사진이 있는 실제 사용자의 영상 크기와 시간은 다를 수 있다.
- 순수 렌더링 시간과 업로드 시간의 분리는 서버에 추가한 `render_duration_ms`, `upload_duration_ms`가 개발 렌더러에 배포된 뒤 작업 로그·DB로 확인해야 한다. 이 측정에서 제시한 `RENDERING`→`COMPLETED`는 그 대체값이 아니다.
- 더 신뢰할 수 있는 기준을 세우려면 배포가 없는 시간대에 반복 수를 늘리고, 사진 포함 여부와 기록 수를 분리한 시나리오로 다시 측정한다.
