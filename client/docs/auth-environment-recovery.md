# 인증 환경별 저장소 분리

운영·개발 토큰은 실제 API 주소(프로토콜, 호스트, 포트, 경로)를 기준으로 별도 저장한다.

- 운영 서버는 기존 Android `mapmory_auth/tokens`, iOS `com.mapmory.ios.auth/guest_tokens` 저장소를 그대로 사용한다. 별도 복사·삭제 마이그레이션 없이 기존 토큰을 보존한다.
- 개발 서버는 주소별 신규 저장소만 읽고 쓴다. 기존 환경 불명 토큰을 개발 저장소로 가져오지 않는다.
- 개발 저장소가 비어 있으면 개발 서버에서 게스트 로그인을 수행해 액세스/리프레시 토큰을 함께 저장한다. 이후에는 해당 개발 토큰을 재사용한다.
- 이미 개발 토큰이 있는데 갱신이 실패한 경우에는 오류를 유지한다. 자동으로 계정을 교체하지 않는다.
- 개발용 계정 초기화 버튼과 확인 다이얼로그는 제공하지 않는다.

기존 토큰을 운영 저장소에 남기는 것은 보존 정책이며 발급 서버가 운영이었다는 증거는 아니다. 운영 기록 접근은 보존된 토큰을 운영 서버가 여전히 인정하는 경우에만 가능하다. 이미 만료·폐기·회전된 토큰은 저장소 분리만으로 복구되지 않는다. 기존 토큰이 개발 발급이었다면 해당 개발 계정은 신규 개발 저장소에서 자동 복원되지 않는다.

앱 식별자 분리는 별도의 장치다. 기존 `.internal` 패키지를 사용하면 운영 앱과 동시에 설치할 수 있다. 같은 앱 설치에서 서버를 바꾸는 경우에는 이 토큰 저장소 분리가 환경 혼용을 막는다.

환경 이름을 별도 도입한다면 API 주소와 하나의 설정으로 묶고 일치 여부를 검증해야 한다. 이름만 바꾸고 서버 주소를 바꾸지 않거나 그 반대인 설정을 허용하면 다시 토큰을 잘못 보낼 수 있다. 현재 주소 기반 키를 임의로 바꾸면 이미 생성된 개발 계정이 달라질 수 있으므로 저장소 이름은 유지한다.
