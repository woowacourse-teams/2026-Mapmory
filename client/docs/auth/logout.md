# 앱 로그아웃

설정에서 소셜 계정 상태를 확인하고 로그아웃을 선택한다. 확인창에서 서버의 계정 기록은 유지되고 기기의 로그인 정보가 삭제된다는 점을 안내한다. 게스트에게는 로그아웃 버튼을 표시하지 않는다.

## 세션 전환

1. 진행 중인 API/업로드, 대기 저장, 영상 생성 요청, 미확정 소셜 로그인이 있으면 로그아웃을 시작하지 않는다.
2. 갱신과 같은 mutex 안에서 현재 refreshToken을 읽는다. 로그아웃을 위해 refresh를 먼저 수행하지 않는다.
3. `LOGOUT` 복구 표식을 영속 저장하고 일반 계정 요청·새 저장을 막는다.
4. `POST /api/v1/auth/logout`에 refreshToken을 보낸다. Bearer는 보내지 않는다. 204 응답을 성공으로 받는다.
5. `LOGOUT:revoked`를 저장하고 기기의 토큰, 기록 목록·지도·통계·영상 작업·기기 사진 사용 인덱스를 정리한다.
6. 표식을 제거하고 화면 세대를 교체하여 지도로 이동한다. 다음 보호 API 호출 때 새로운 게스트를 발급한다.

새 게스트의 기록은 이전 계정의 기록과 별개이다. 다시 소셜 로그인하면 해당 계정의 서버 기록을 조회한다. 기존 소셜 계정으로 전환할 때 게스트 기록이 자동 병합되지는 않는다.

## 실패와 재시작

- 로그아웃 표식을 저장하지 못하면 서버에 요청하지 않는다.
- 서버 응답 유실 시 결과가 불확실하므로 재시도한다. 확인한 backend-develop revoke는 미존재/이미 폐기된 refreshToken에도 성공하며 반복 호출할 수 있다.
- 토큰 삭제나 캐시 삭제 실패 시 이전 세션을 다시 사용하지 않는다. 닫을 수 없는 재시도 안내를 표시한다.
- 재시작 시에도 LOGOUT 표식으로 요청·캐시 접근·저장을 막는다. `:revoked` 표식이 있으면 서버 폐기를 반복하지 않고 기기 정리부터 재개한다.
- iOS Keychain 삭제 결과를 검사하며 삭제 실패를 성공으로 처리하지 않는다.

로그아웃은 이 기기의 맵모리 세션 종료이다. Google/카카오 계정 탈퇴, 앱 연결 해제, 다른 앱의 제공자 로그아웃은 수행하지 않는다. 서버 API는 refreshToken을 폐기하며, 이미 발급된 accessToken의 서버 측 즉시 무효화를 보장하는 계약은 아니다. 클라이언트는 이전 토큰의 사용을 중단한다.

## 관측과 검증

`auth_logout_completed`: source=settings, provider, outcome(success/blocked/pending/failure), stage, duration_ms. `logout`은 기기 토큰·캐시 정리가 완료된 성공에만 기록한다. 토큰·회원명·원본 오류 메시지는 이벤트에 넣지 않는다.

공통 회귀 테스트는 응답 유실 후 재시작, 토큰 삭제 실패, 캐시 삭제 실패, 중복 로그아웃/동시 refresh, 미확정 로그인·저장 중 차단을 검증한다. HTTP 계약 테스트는 Bearer 없는 refreshToken body와 204 처리를 확인한다. Android 모의 UI 테스트는 취소, 성공 후 지도·그룹 재로그인 안내, 실패 후 재시도를 검증한다. 실제 사용자 계정의 서버 로그아웃 성공 검증은 모의 테스트와 별개이다.

2026-10-26 검증: 공통 JVM 테스트 441개 실패 0, Android debug/app-test 빌드 성공, 에뮬레이터 GroupSocialLoginTest 6개 성공(최종 로그아웃 UI 2개 재확인), iOS Debug 시뮬레이터 전체 빌드 성공. 휴대폰 연결이 끊겨 실제 계정의 로그아웃과 최종 APK 설치는 미검증이다.
