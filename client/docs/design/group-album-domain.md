# 그룹 앨범 도메인

2026-10-23. 개인 기록을 앨범에 연결하는 모델이다. API/DB 계약은 아직 없으며, 그룹 화면은 개발용 미리보기다.

## 객체와 책임

| 객체 | 책임 |
| --- | --- |
| `TravelGroup` | 그룹 ID·이름, 전체 멤버십, 생성·참여·이름 변경·나가기 후 멤버십 상태 |
| `GroupInvitation` | 발급자·그룹 참조, 코드·토큰, 24시간 유효성 |
| `TravelAlbum` | 그룹 참조와 개인 기록 연결 집합, 멤버·소유권 확인 후 공유 |
| `OwnedRecordReference` | 기록 영역이 제공하는 기록 ID·소유 회원 ID |
| `AlbumRecordLink` | 개인 기록 참조. 사진과 원본 기록을 소유하지 않음 |
| `RecordPhotos` | 개인 기록 상세의 전체 사진 ID. 사진 제거 결과를 `PhotoRemoved` 또는 `RecordDeleted`로 결정 |
| `GroupActor` | 인증 계층이 제공하는 회원 ID·게스트/소셜 여부·표시 이름 |
| ID 값 객체 | 서로 다른 종류의 ID 혼용 방지 |

그룹과 앨범은 별도 애그리거트다. 개인 기록은 그룹에 속한 객체가 아니며 앨범은 ID로 참조한다. 소셜 로그인 이름은 화면 표시 값이고 멤버 식별에는 사용하지 않는다.

## 도메인 규칙

- 소셜 회원만 생성·참여할 수 있다. 생성자는 첫 멤버이며 최대 30명이다.
- 중복 멤버십과 정원 초과를 구분한다. 현재 멤버는 누구나 이름 변경과 초대 발급을 할 수 있다.
- 이름은 공백만으로 구성할 수 없다. 길이·중복 정책은 미정이다.
- 초대는 발급 시각부터 24시간 미만 유효하다. 발급 전·만료 시각·다른 그룹 초대를 거절한다. 일회용 초대는 아니다.
- 초대 코드는 공백 없는 6글자다. UI의 숫자 입력과 최종 코드 문자 계약은 별도 확인이 필요하다.
- 공유는 현재 멤버이면서 해당 기록 소유자만 가능하다. 같은 앨범에 같은 기록을 중복 연결할 수 없다.
- 개인 기록 수정은 이를 참조하는 앨범에도 반영한다. 사용자에게 별도 공유 내리기를 제공하지 않는다.
- 개인 기록의 마지막 사진 삭제는 기록 삭제 결과다. `RecordPhotos`는 전체 사진 목록을 요구하며 앨범 페이지에서 개수를 추정하지 않는다. 소유권 확인과 실제 저장/삭제는 인증된 기록 작업 및 서버 책임이다.
- 빈 그룹·빈 앨범 상태는 표현할 수 있다. 자동 삭제 정책은 아직 결정하지 않았다.
- 그룹·앨범은 변경 시 새 객체를 반환하고 컬렉션을 복사한다.

## 서버와 클라이언트 경계

- 그룹 나가기의 앨범 연결 정리는 서버의 원자적 작업이다. 클라이언트는 응답 후 권한·앨범을 다시 조회한다.
- `TravelGroup.leave`는 새 멤버십 상태만 반환한다. 지연 재생 가능한 `GroupDeparture`, `TravelAlbum.applyDeparture`는 제거했다. 과거 나가기 결과로 재가입 후 연결을 지우는 경로를 제공하지 않는다.
- `TravelAlbum.unshare`는 제거했다. 사용자 삭제는 개인 기록 작업이며, 원본 삭제에 따른 연결 정리는 서버 책임이다. 앨범 객체에 원본 삭제 책임을 넣지 않는다.
- `restore`는 신뢰할 수 있는 전체 스냅샷 복원용이다. 페이지 일부로 권한·정원을 판정하면 안 된다. 클라이언트 검증은 서버 권한 검증을 대체하지 않는다.
- 초대 토큰 검증·코드 조회·생성, 로그인, 계정 탈퇴·원본/캐시 삭제, 저장과 연결의 정합성은 서버/외부 계층이 이어야 한다.

## UI 작업 상태

- `GroupPreviewState`는 샘플 화면 전환·입력·삭제·저장 단계를 조율한다. 서버 요청을 수행하지 않는다.
- `GroupSheet`는 화면 종류, `GroupSaveStage`는 업로드·기록 저장·앨범 연결·완료를 타입으로 표현한다.
- `GroupSaveJob`는 새 앨범/기존 앨범 대상과 사진/기록 입력을 함께 보관한다. 빈 사진 선택이나 대상 없는 저장을 거절한다.
- 사진 저장은 업로드부터, 기존 기록 공유는 연결부터 시작한다. 실패 후 재시도는 같은 입력·대상·단계를 유지한다.
- 상태는 Saver로 직렬화하며 화면 복원 후에도 작업 대상을 유지한다. 뒤로 제스처 취소는 별도 화면 스냅샷을 복원한다.
- 삭제 판단은 개인 기록 모델의 결과를 표시한다. 샘플 개인 기록 목록은 앨범 목록과 별도로 보관한다.

## 확정 정책과 남은 작업

- 개인 기록 저장 사전 안내는 보류한다. 초대 참여 확인은 한 번만 한다.
- 실패 시 네트워크 확인과 실패한 최대 10장 묶음 재시도를 안내한다. 현재 10장은 URL 발급 단위이며 개별 전송 롤백을 보장하지 않는다. 완료 전송 재사용은 실제 업로드 계층에서 연결해야 한다.
- 응답 수신 실패의 재요청/결과 확인 정책은 보류한다. 현재 결과 확인 버튼은 미리보기 상태 전환이다.
- 앨범 제목·기간·대표 사진 기준, 기존 기록 공유 시 새/기존 앨범 선택, 회원당 기록 연결 개수, 마지막 멤버·마지막 기록 삭제 시 앨범/그룹 처리 등은 미정이다.
- 실제 삭제·업로드·연결 API와 UI 연결, 백엔드 동시성 검증, 실기기 검증은 후속 작업이다.
