# 그룹 앨범 UI · 화면과 상태 목록

기준: `찐찐찐찐찐 최종.excalidraw` (Process Modeling v3.2), 2026-10-22.
브랜치: `and/feat/group-album-ui` (develop `72446324`에서 분기).
이번 단계는 UI 구현이다. 서버 연결 및 API 계약 변경은 별도다.

## 최신 모델

- 그룹은 여러 여행 앨범을 가진다. 같은 여행은 앨범 카드 하나로 표시한다.
- 저장되는 여행 기록은 각자의 개인 기록이며, 앨범이 그 기록 ID들을 참조한다.
- 앨범 상세는 연결된 기록들의 사진을 모아 보여주고 사진마다 올린 사람의 소셜 로그인 이름을 표시한다.
- 앨범에 사진을 붙이면 내 기록이 생기거나 연결된다. 다른 멤버의 기록을 수정하지 않는다.
- 별도로 올리기는 새 앨범으로 이어진다. 내 기록을 그룹에 공유해도 개인 기록은 남는다.
- 공유할 사진만 따로 고르기와 기록 전체 삭제는 보류한다. 이전 Figma의 해당 단계는 구현 기준으로 쓰지 않는다.
- 내 지도·통계는 내 기록 기준이다. 앨범에 붙인 내 기록도 포함한다.

## 상태 경계

- 조회 상태: `Loading / Empty / Content / Error`; 새로고침은 기존 내용을 유지한다.
- 입력 상태: 입력값·검증 오류·제출 중을 별도로 가진다. 조회 상태 하나에 모두 섞지 않는다.
- 대상: 새 앨범 생성과 기존 앨범 기여를 명시적으로 구분한다. 저장 대기 중에도 groupId·albumId·요청 식별자를 보존한다.
- 사진 표현: photoId, 개인 recordId, 업로더 ID·소셜 로그인 이름, 썸네일·원본, 촬영일, 내 사진 여부가 필요하다.
- 초대: token/code, 그룹 미리보기, 만료 시각, 로그인 복귀 목적지를 유지한다.
- 일회성 효과: 코드 복사, OS 공유창, 완료 안내, 화면 이동, 다운로드 결과는 지속 화면 상태와 분리한다.
- 성공 표시는 업로드만 끝났을 때가 아니라 기록 저장과 그룹 앨범 연결까지 확인했을 때 표시한다.
- 결과 확인 필요 상태에서는 곧바로 같은 저장을 다시 보내지 않는다. 요청 식별자로 결과를 확인하는 연결이 필요하다.

## 기존 UI 재사용

- `NewTripRecordFlowScreen`: 지역·장소·사진 선택 흐름. 새 앨범 / 기존 앨범 대상을 추가하는 방향으로 검토한다.
- `MapmoryPhotoViewer`, `MapmoryAsyncImage`: 사진 표시·넘겨보기. 업로더 표기·내 사진 메뉴가 추가로 필요하다.
- `TripRecordItemUiState`, `TripRecordPhotoUiState`: 개인 기록 표현 유지. 그룹·앨범 UI 모델은 별도로 둔다.
- `TripRecordPalette`: 라이트 카드 `surface`(흰색), 테두리 `border`(`#E4E9E6`) 1dp, 강조 `primary`(`#4D9272`), 화면 `pageBackground` 재사용. 별도 초록 카드 배경을 만들지 않는다.
- 버튼은 기본 48dp / 하단 주요 동작 56dp, 모서리 14dp, 라벨 16/24 기준. 화면당 같은 기능의 진입 버튼을 중복 배치하지 않는다.
- 라이트·다크 테마 모두 기존 팔레트를 사용한다. 태그 UI는 그룹 MVP에 넣지 않는다.

## 구현 순서

1. 그룹·앨범 표시 모델과 프리뷰 데이터, 조회·입력·작업 상태 정의.
2. 내 그룹 목록 / 그룹 홈의 빈 상태·목록 / 앨범 카드 / 앨범 상세를 stateless Screen으로 구현.
3. 그룹 만들기 / 초대 / 코드 입력 / 참여 확인 시트·다이얼로그 구현.
4. 기존 사진 선택·뷰어와 그룹 대상 연결, 내 기록 공유·사진 붙이기·저장 상태 UI 구현.
5. 이름 변경·나가기·내 사진 삭제 확인과 오류·재시도 상태 구현.
6. 실제 API 연결은 계약 확인 후 진행. 프리뷰의 성공을 서버 저장 성공처럼 처리하지 않는다.

## 결정이 필요한 부분

- 새 앨범 이름을 별도로 입력하는지, 첫 기록의 장소·기간에서 유도하는지.
- 기존 내 기록 공유 시 기존 앨범을 고르는지, 새 앨범으로 여는지의 UI와 API 계약.
- 기존 앨범에 사진을 붙일 때 장소·기간을 고정하는 범위.
- 그룹 이름 길이·중복 허용·코드 문자 종류는 문서에 확정 규칙이 없어 임의의 제약을 추가하지 않는다.
- 마지막 멤버 나가기, 기준 기록 작성자 나가기·탈퇴, 앨범의 마지막 사진 삭제 후 처리.
- 그룹 지도·통계는 도식에 있으나 MVP 상세 화면 우선순위는 별도 결정한다.

미결정 항목은 UI에서 확정 정책처럼 안내하지 않는다.

## 2026-10-22 UI 구현 현황

- 하단 내비게이션에 그룹 탭 추가: 지도·일지·그룹·통계·설정.
- 내 그룹 목록/빈 상태/로딩/오류, 그룹 홈의 앨범 목록/빈 상태, 앨범 사진 그리드, 업로더를 표시하는 전체 사진 뷰어 구현.
- 이름 입력, 6자리 숫자 코드 입력, 초대 발급, 앨범 추가 방식, 사진 추가 안내 시트 구현.
- 개발 도구가 활성화된 빌드에서 `그룹 UI 미리보기`를 누르면 샘플 그룹 → 앨범 → 사진을 탐색할 수 있다. 앨범 없는 상태도 전환 가능하다.
- 샘플 데이터는 실제 그룹/초대가 아니며 저장하지 않는다. 서버가 필요한 제출은 준비 중 안내를 표시한다.
- 실제 소셜 로그인 게이트, 초대 발급/조회/수락, 그룹 관리, 사진 선택/공유/업로드/재시도/다운로드/삭제는 후속 연결 범위다.
- 사진은 URI 기반으로 기존 MapmoryAsyncImage를 재사용하며, 현재 샘플 URI가 없으므로 자리표시자를 표시한다.
- 공통/Android 컴파일 및 그룹 탭 상태 복원 회귀 테스트 통과. JVM 렌더링으로 4개 기본 화면 확인. 실제 기기 및 iOS 동작은 미확인.

## 자체 리뷰 수정

- 업로더는 내부 멤버 ID와 소셜 로그인 표시 이름을 분리한다. 같은 이름이어도 다른 멤버는 합치지 않는다.
- 그룹 내부 화면의 edge-back/forward 및 제스처 취소 복원을 등록했다.
- 그룹/앨범별 SaveableStateHolder로 목록 위치를 복원하고 사진 뷰어는 열기 세션별로 페이지 상태를 보존한다.
- 미리보기에서 그룹 생성, 초대 미리보기/참여 확인/정원/만료, 장소와 샘플 사진 선택, 내 기록 선택, 업로드/기록 저장/앨범 연결/실패/재시도/결과 확인 상태를 탐색할 수 있다.
- 처리 단계는 미리보기 버튼으로 전환하며 실제 서버 호출, 기기 사진 선택, 백그라운드 업로드는 수행하지 않는다.

## 2026-10-23 사용자 플로우 검토 결정

- 사진 추가 시 개인 기록에도 저장된다는 사전 안내는 보류한다.
- 개인 기록의 수정은 그 기록을 참조하는 공유 앨범에도 동일하게 반영한다.
- 사용자에게 별도 공유 내리기 기능을 제공하지 않고 삭제 흐름으로 통합한다. 클라이언트의 `unshare`는 제거했다. 개인 기록 삭제와 서버의 연결 정리로 처리한다. 삭제 대상과 연쇄 처리의 구체적인 구현은 후속 작업이다.
- 그룹 홈에서 시작하는 공유는 해당 그룹을 대상으로 한다. 새 앨범 생성인지 기존 앨범 연결인지는 별도 결정 사항이다.
- 초대 미리보기에서 참여를 한 번 확인한다. 참여하기 → 완료 안내 → 그룹 보기로 진행하며 별도의 참여 확인 시트는 제거한다.

## 2026-10-23 예외 처리 범위

- 앨범 연결과 개인 기록 저장의 정합성은 백엔드에서 보장한다. 응답 수신 실패 시 재요청/결과 확인 정책은 보류한다.
- 업로드 실패 시 네트워크 연결 확인 안내와 실패한 최대 10장 묶음의 재시도를 제공한다. 10장은 현재 URL 발급 요청 단위이며, 개별 전송 성공을 되돌리는 트랜잭션은 아니다. 실제 재시도는 완료된 전송을 재사용하도록 저장 계층에서 이어야 한다.
- 개인 기록의 마지막 사진을 삭제하면 해당 기록도 삭제한다. 앨범 전체의 마지막 사진과 개인 기록의 마지막 사진은 구분한다. 다른 회원의 기록은 유지한다. 빈 앨범의 유지/삭제 정책은 계속 미정이다.
- 이번 UI는 샘플 데이터의 내 사진 삭제 확인과 삭제 후 뷰어 닫기, 단계별 실패/재시도 문구를 제공한다. 실제 원본/기록 삭제 및 업로드 묶음 재시도 API 연결은 후속 작업이다.

## 도메인 리뷰 반영

- `GroupPreviewState`로 화면 전환과 샘플 작업 조율을 분리하고, `GroupSheet`/`GroupSaveStage`로 문자열 상태를 대체했다.
- `GroupSaveJob`가 대상 그룹·앨범과 사진/기록 입력을 보존한다. 기존 기록은 기록 ID를 선택하여 연결 단계부터 시작한다.
- 마지막 사진 판단은 앨범 UI 모델에서 제거했다. 전체 개인 기록 사진을 갖는 `RecordPhotos`가 삭제 결과를 결정한다.
- 클라이언트 `GroupDeparture`/`applyDeparture`/`unshare`를 제거했다. 나가기·원본 삭제의 연결 정리는 서버 응답 재조회로 반영한다.

## 로그인 PR 위의 독립 미리보기 (2026-10-27)

소셜 로그인 PR #497을 기반으로 한다. 운영 그룹 탭의 로그인/실제 목록은 유지한다. 개발자 도구가 있는 환경에서만 그룹 탭 상단의 `그룹 앨범 화면 미리보기`로 별도 경로에 진입한 뒤 기존 `그룹 UI 미리보기`를 켠다. 샘플 그룹·초대·앨범·사진·저장 상태는 이 경로에서만 다루며 실제 계정의 멤버십/기록으로 표시하거나 저장하지 않는다.

서버 그룹 API 연결과 사용자 로그인 복귀는 로그인 PR과 별개이며, 이 PR은 기존 샘플 도메인·화면·상태 복원만 다룬다. 미리보기 행동 GA는 #486에서 후속 적용한다.

미리보기는 임시 화면으로 취급한다. 다른 하단 탭으로 이동하면 미리보기 경로를 제거하고, 이후 그룹 탭은 계정의 실제 그룹 목록으로 돌아온다. 앨범·사진 화면 내부의 뒤로가기 및 취소된 제스처 상태 복원은 유지한다.

분리 후 검증: JVM 테스트 430개, Android debug/androidTest 빌드, 에뮬레이터의 개발용 미리보기 진입·앨범 조회·그룹 탭 복귀와 일반 환경에서 샘플 숨김 테스트 2개 통과. 실제 그룹 API 작업은 이 검증에 포함하지 않는다.
