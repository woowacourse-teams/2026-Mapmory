# 그룹 제목·뒤로가기·초대 코드 개선 계획

- 작성일: 2026-11-05
- 브랜치: `and/feat/login-ui-polish`
- 상태: 계획 작성. 이번 요청에서는 기능 코드를 변경하지 않는다.

## 1. ‘내 그룹’ 제목 정렬

현재 `GroupScreens.kt`의 `GroupListScreen`은 좌우 24dp, 제목 위아래 24dp, 글자 28sp를 사용한다. 설정 화면은 좌우 20dp와 헤더 세로 18dp를 사용해 시작 위치가 다르다.

- 설정 등 주요 탭의 실제 헤더와 안전 영역을 비교하여 제목 기준선을 맞춘다.
- 좌우 여백은 20dp, 헤더 세로 여백은 18dp를 기준으로 정리하고 제목 스타일도 다른 탭과 맞춘다.
- ‘내 그룹’ 문구는 유지한다. 위치 조정을 위해 불필요한 영문 제목을 추가하지 않는다.
- 새 그룹/코드로 참여 버튼과 목록 카드의 좌우 시작선도 제목과 일치시킨다.
- 로딩·빈 목록·오류 상태에서도 제목 위치를 동일하게 유지한다.
- 작업 트리에 이미 `GroupScreens.kt` 수정이 있으므로 구현 전 diff를 확인하고 기존 변경을 보존한다.

## 2. 시스템 뒤로가기와 화면 뒤로가기 통일

### 현재 확인된 구조

`LiveGroupContent`는 `PlatformBackHandler`와 `MapmoryBackHandlerRegistry` 양쪽에 뒤로가기를 등록한다. 내부에서는 `AlbumNavigationState.back()`을 먼저 호출하고 그룹 상태의 `back()`으로 이어진다. `App.kt`에는 registry 처리 후 상위 내비게이션으로 넘어가는 경로가 있다. 앨범 화면의 헤더 뒤로가기는 별도 콜백도 사용한다.

따라서 내부 뒤로가기 코드가 아예 없는 상황은 아니다. 실제 기기에서 지도 이동을 재현한 뒤 핸들러 등록 순서·활성 조건·owner ID·이벤트 소비 여부를 확인해야 원인을 확정할 수 있다.

### 목표 동작

| 현재 화면 | 시스템 뒤로가기 / 화면 뒤로가기 결과 |
| --- | --- |
| 초대·관리 등의 모달 | 모달 닫기 → 원래 화면 |
| 사진 크게 보기 | 사진 닫기 → 해당 앨범 상세 |
| 기록 선택 화면 | 선택 화면 닫기 → 해당 앨범 상세 |
| 앨범 상세 | 해당 그룹의 앨범 목록 |
| 그룹 안 앨범 목록 | 내 그룹 목록 |

그룹/앨범의 내부 화면이 남아 있는 동안 지도 탭으로 이동하지 않는다. 최상위 ‘내 그룹’ 목록은 돌아갈 내부 부모가 없으므로 기존 탭 루트 정책을 유지한다. 이 계획의 핵심은 중간 단계를 건너뛰는 현상을 수정하는 것이다.

### 구현 순서

1. 내 그룹 → 그룹 → 앨범 → 사진 경로에서 시스템 버튼·뒤로가기 제스처·헤더 버튼을 각각 재현한다.
2. `App.kt`, `MapmoryNavHost.kt`, `MapmoryBackHandlerRegistry`, Android `PlatformBackHandler`의 디스패치와 그룹 등록 생명주기를 추적한다.
3. 시스템과 헤더가 동일한 내부 상태 전환을 사용하도록 정리한다. 한 번의 뒤로가기는 가장 위의 화면 하나만 닫고, 처리했으면 상위 내비게이션에 전달하지 않는다.
4. 앨범 상세·사진·선택 화면·모달을 포함해 내부 상태가 있을 때 핸들러가 활성화되는지 확인한다. 내부 단계가 없을 때만 상위 정책에 맡긴다.
5. 앨범 목록 복귀 시 필요한 새로고침을 보존하고, 뒤로간 뒤 늦게 도착한 API 응답이 상세 화면을 다시 열지 않게 revision 검사도 확인한다.
6. 기록 생성 후 그룹/앨범 복귀, 화면 재생성, 그룹 탈퇴, 처리 중 뒤로가기와 iOS 제스처 취소/복원 동작을 회귀 확인한다.

예상 변경 대상: `LiveGroupContent.kt`, `LiveAlbumContent.kt`, `AlbumNavigationState.kt`, 필요 시 앱 내비게이션 계층. 원인 확인 없이 전체 앱 백스택 구조를 변경하지 않는다.

## 3. 초대 코드 터치 복사

현재 `LiveGroupContent`의 초대 화면은 코드를 일반 `Text`로 표시하고, 별도 ‘초대 코드 복사’ 버튼에서 클립보드 기록과 완료 안내를 수행한다.

- 발급된 코드 표시 영역을 누르면 즉시 해당 코드만 클립보드에 복사한다. 확인창은 띄우지 않는다.
- 코드 영역과 기존 복사 버튼이 동일한 복사 함수를 사용하게 한다. 기존 버튼은 명시적인 대체 수단으로 유지한다.
- 기존 ‘초대 코드를 복사했어요’ 안내를 재사용한다. 클릭 한 번에 중복 안내가 발생하지 않게 한다.
- 코드 주변을 포함해 최소 48dp 터치 영역을 확보하고, 버튼 역할 및 ‘초대 코드 복사’ 접근성 라벨을 제공한다.
- 코드 발급 전이나 발급 실패 시 복사 영역을 노출하지 않는다. 실제 표시된 코드와 복사한 문자열이 일치해야 한다.
- 화면 진입/코드 발급만으로 복사하지 않는다. 사용자가 코드 또는 복사 버튼을 누른 경우에만 복사한다.
- 데모용 `GroupRoute.kt`에도 같은 UI가 있다면 공통 동작을 맞추되 실제 서버 경로를 우선 검증한다.

## 4. 검증 및 완료 기준

- 제목: 다른 주요 탭과 좌우 정렬 및 상단 기준선 비교. 라이트/다크, 큰 글씨, 작은 화면에서 잘림 없음.
- 뒤로가기: 사진 → 앨범 상세 → 앨범 목록 → 내 그룹 순서가 시스템과 헤더에서 동일함. 중간에 지도 이동이나 한 번에 두 단계 이동 없음.
- 복구: 로딩 중 뒤로가기 후 늦은 응답이 닫힌 화면을 다시 열지 않음. 모달 닫기와 그룹 탈퇴 후에도 올바른 화면 유지.
- 복사: 코드 터치와 기존 버튼 모두 정확히 같은 코드를 복사하고 완료 안내 표시. 접근성 탐색으로도 실행 가능.
- 테스트: 내부 뒤로가기 우선순위와 상위 전달 여부를 검증하는 상태/registry 테스트를 추가 또는 보완하고 `:shared:jvmTest` 실행.
- 빌드: Android 디버그 빌드, 공통 코드 변경에 대한 iOS 컴파일 확인. 시스템 뒤로가기 문제의 완료 판정에는 Android 실기기 또는 에뮬레이터 재현·수정 확인을 포함한다.

계획 작성 시점에는 실제 기기 재현과 원인 확정, 기능 구현 및 검증을 수행하지 않았다.
