# 그룹 새로고침·일지 영상 진입 UI 개선 계획

- 작성일: 2026-11-05
- 상태: 계획 작성 / 기능 구현 전
- 대상: 요청 1~5번. 비어 있는 6번은 제외한다.
- 기존 로그인·그룹 UI 작업을 보존하며 같은 작업 브랜치에서 진행한다.

## 1. 그룹 화면 당겨서 새로고침

‘위로 스크롤 하면 업데이트’는 **목록 최상단에서 아래로 당겨 새로고침**하는 일반적인 동작으로 해석한다. 단순히 목록을 위쪽으로 탐색할 때마다 요청하지 않는다.

현재 `GroupRefreshContainer`와 `LiveGroupContent`, `LiveAlbumContent`에 이미 pull-to-refresh 연결이 있다. 새 기능을 중복 추가하기보다 실제로 제스처가 전달되지 않는 상태를 보완한다.

- 내 그룹 목록, 그룹 안 앨범 목록, 앨범 상세의 기록 목록에서 당겨서 최신 내용을 조회한다.
- 빈 목록·오류·항목이 적어 화면이 차지 않는 상태에서도 스크롤 입력이 상위 새로고침 컨테이너로 전달되게 한다.
- 최초 진입 로딩과 사용자가 요청한 새로고침 상태를 분리한다. 새로고침 중 기존 목록을 없애거나 스크롤을 불필요하게 초기화하지 않는다.
- 중복 요청을 막고 성공·실패·취소 시 표시를 해제한다. 실패 시 기존 내용과 재시도 가능한 오류 안내를 유지한다.
- 사진 전체보기·입력 모달 등에서는 새로고침을 막고, 화면 이탈 후 응답이 현재 화면을 덮어쓰지 않는지 확인한다.

예상 파일: `GroupRefreshContainer.kt`, `GroupScreens.kt`, `LiveGroupContent.kt`, `LiveAlbumContent.kt`.

## 2. ‘일지 영상 만들기’ 안내 문구

현재 `TripRecordListScreen.kt`의 `TripTimelineVideoEntry`에는 ‘내 여행 기록을 타임라인 영상으로 모아요’가 표시된다.

- 기존 설명을 삭제하고 **‘2개국 이상에 여행 기록을 남기면 만들 수 있어요’**로 교체한다.
- 긴 문구가 작은 화면이나 큰 글씨에서 잘리지 않도록 한 줄 제한을 제거하거나 두 줄을 허용한다.
- 2개국 이상이면 설명을 ‘일지 영상을 만들 준비가 됐어요’로 바꾸어 충족 상태를 알린다.
- 이 조건은 카드 설명과 실제 새 영상 생성 가능 여부에 동일하게 적용한다. 기존 생성 완료 영상 조회·다운로드·진행 중 작업 복구를 막지 않도록, 카드 진입과 생성 버튼 제한을 분리한다.

## 3. 재생 아이콘 대신 국가 수 진행 원

카드 왼쪽의 ‘▶’ 아이콘을 고정 크기의 원형 진행 표시와 가운데 숫자로 교체한다.

| 기록이 있는 서로 다른 국가 수 | 표시 | 원형 진행률 |
| --- | --- | --- |
| 0개국 | `0/2` | 0% |
| 1개국 | `1/2` | 50% |
| 2개국 이상 | `2/2` | 100% |
| 아직 조회 중 / 조회 실패 | 로딩 / 확인 불가 표시 | 0개국으로 오인시키지 않음 |

- 숫자는 최소 조건 충족도를 표현하므로 3개국 이상도 `2/2`로 고정한다.
- 진행선은 테마 `primary`, 배경선은 표면/경계 의미 색상, 숫자는 본문 의미 색상을 사용한다.
- 접근성에는 ‘영상 생성에 필요한 2개국 중 1개국 기록 완료’처럼 상태를 전달한다.
- 국가 수는 사진 수·기록 수가 아니라 **전체 개인 기록의 서로 다른 국가 식별자 수**로 계산한다. 같은 나라의 여러 도시와 여러 기록은 1개국이다. 국내 기록도 한국 1개국으로 포함한다.
- 현재 화면에서 로딩한 페이지나 지역 필터 결과만 세지 않는다. 기존 전체 여행 통계/국가 집계 데이터의 재사용 가능 여부를 먼저 확인하고, 없다면 전체 범위를 보장하는 데이터 경로를 설계한다.
- 국가를 알 수 없는 기록은 임의의 국가로 세지 않는다. 기록 생성·삭제·계정 변경 후 집계를 갱신한다.
- 현재 `ShareVideoRepository`에는 생성·작업 조회·다운로드 API만 있으므로 국가 조건을 검증하는 서버/집계 경로는 구현 전에 확인해야 한다. 클라이언트 표시만 바꾸고 실제 생성 조건이 일치한다고 가정하지 않는다.

예상 파일: `TripRecordListScreen.kt`, 기록 목록 route/state와 국가 집계 제공 코드, 필요 시 `TripTimelineVideoDialog.kt`의 생성 가능 조건.

## 4. ‘나의 여행’ 아래 설명 삭제

`TripRecordListScreen.kt` 헤더에서 아래 레이아웃별 부제 영역을 삭제한다.

- 사진: ‘사진을 따라 그날의 기억으로’
- 타임라인: ‘언제, 어디서 남긴 기록인지 차례로’
- 여행지별: ‘여행 기록을 여행지별로 모아보기’

제목·영문 상단 라벨·총 기록 수·보기 전환은 유지한다. 부제 전용 여백도 제거해 빈 공간이 남지 않게 한다. 지역별 화면의 ‘이 지역에 남긴 여행 기록’은 별도 문맥 안내이므로 이번 삭제 범위에서 유지한다.

## 5. 그룹 최초 로딩을 가운데 표시

`GroupAccountRoute`의 계정 복원 로딩은 현재 정렬 없는 `Box` 안에 있어 좌상단에 표시될 수 있다. 그룹 목록은 별도 중앙 정렬을 이미 사용한다.

- 계정 복원 및 초기 그룹/앨범 데이터 조회의 로딩을 **하단 탭바를 제외한 사용 가능한 콘텐츠 영역의 가로·세로 중앙**에 배치한다.
- 그룹 목록의 제목/버튼이 유지되는 상태에서는 그 아래 목록 영역 중앙에 표시한다.
- 처음 불러올 때 원형 인디케이터가 중복으로 나타나지 않게 한다.
- 당겨서 새로고침 인디케이터는 제스처와 연결된 상단 중앙에 유지한다. 사진 업로드 등 개별 작업의 진행 표시와 초기 화면 로딩을 구분한다.

예상 파일: `GroupAccountRoute.kt`, `GroupScreens.kt`, `LiveAlbumContent.kt`.

## 6. 구현 순서 및 검증

1. 기존 새로고침이 실패하는 화면 상태와 국가 집계 데이터 경로를 확인한다.
2. 그룹 스크롤 전달 및 중앙 로딩 배치를 수정한다.
3. 일지 헤더 부제 제거, 영상 카드 문구·원형 진행 표시를 적용한다.
4. 전체 국가 집계와 생성 조건을 연결하고 기존 영상 작업 복구를 확인한다.
5. JVM 테스트와 Android 빌드, iOS 공통 코드 컴파일을 수행한다.

필수 검증:

- 그룹 목록의 빈 상태/오류/짧은 목록/긴 목록에서 새로고침 성공 및 실패, 연속 당김 시 중복 요청 방지.
- 그룹·앨범 진입 시 중앙 로딩, 새로고침 시 기존 콘텐츠와 내부 뒤로가기 상태 유지.
- 국가 0/1/2/3개, 같은 국가의 여러 기록, 국내 여러 도시, 페이지 분할, 지역 필터, 기록 삭제와 계정 전환 시 정확한 진행 표시.
- 집계 미완료·실패를 `0/2`로 표시하지 않음. 2개국 미만 새 생성 제한과 기존 작업 조회/복구 양립.
- 라이트/다크 및 그린/블루, 큰 글씨에서 원·숫자·안내 문구가 잘리지 않음.
- 국가 중복 제거/진행률/생성 조건의 의미 있는 상태 테스트를 보완하고, 스크롤 제스처와 로딩 위치는 실제 기기 또는 에뮬레이터로 검증한다.

이 문서는 계획이며 코드 변경이나 실기기 검증을 완료한 상태가 아니다.
