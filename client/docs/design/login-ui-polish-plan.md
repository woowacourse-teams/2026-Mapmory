# 로그인·내 정보 UI 개선 계획

- 작성일: 2026-11-05
- 기준: 최신 `origin/develop`을 반영한 `develop`
- 작업 브랜치: `and/feat/login-ui-polish`
- 상태: 계획 작성 완료 / 기능 구현 전
- 범위: 그룹 진입 로그인 화면과 설정의 계정 영역. Compose 공통 코드 변경이므로 Android·iOS 모두 확인한다.

## 1. 현재 구현과 개선 방향

| 요청 | 현재 구현 | 개선 방향 |
| --- | --- | --- |
| 최근 로그인 강조 | 소셜 버튼 위에 우측 정렬 텍스트만 표시 | 버튼 바깥 강조 테두리와 꼬리가 있는 말풍선 |
| 그룹 로그인 안내 | `계정 연결` 제목과 기록 전환 설명 | 그룹 이용을 위해 로그인이 필요하다는 안내를 우선 표시 |
| 디자인 시스템 통일 | 로그인은 기본 Material 배치, 설정 계정은 일반 텍스트 나열 | 앱 의미 색상·타이포·여백·카드 규칙 적용 |
| 계정 확인 다시 시도 제거 | 그룹 로그인 영역에 상시 표시, 설정에는 복원 실패 시 표시 | 두 위치에서 제거하고 화면 재진입 시 복구 경로 유지 |
| 내 정보 카드 | 닉네임·로그인 제공자와 로그아웃만 표시 | `내 정보` 카드에 왼쪽 로그인 정보, 오른쪽 20dp × 20dp 프로필 이미지 |

## 2. 최근 로그인 말풍선과 외곽 테두리

- `recentLoginProvider`와 일치하는 버튼에만 표시한다. 값이 없거나 해당 제공자가 현재 기기에서 지원되지 않으면 표시하지 않는다.
- 소셜 버튼을 감싸는 레이아웃을 만들고, 버튼 바깥에 2dp 강조 테두리를 그린다. 버튼과 테두리 사이에는 4dp 여백을 둔다.
- 테두리와 말풍선 배경은 `TripRecordPalette.current.primary`, 말풍선 텍스트는 `onPrimary`를 사용한다.
- 말풍선은 버튼 우측 상단 바깥에 배치하고 아래쪽 꼬리가 버튼을 가리키게 한다. 문구는 `최근 로그인`으로 유지한다.
- 말풍선 높이와 꼬리 영역을 레이아웃에 실제로 확보한다. 음수 offset에만 의존하여 상위 스크롤/clip에서 잘리거나 앞 버튼과 겹치지 않게 한다.
- 최근 로그인 여부와 무관하게 버튼 본체의 너비와 정렬을 일치시킨다. 글자 확대 시 말풍선 높이는 내용에 따라 늘어난다.
- 말풍선은 별도 클릭 대상이 아니다. 버튼 접근성 설명에 최근 로그인 상태를 전달하고 중복 읽기를 피한다.
- 제공자 버튼의 브랜드 색·로고·서체는 기존 `docs/social-login-branding.md` 기준을 유지한다. 앱 테마 강조는 브랜드 버튼 외부에 적용한다.

## 3. 로그인 문구와 디자인 시스템

### 문구

- 화면 제목: `그룹`
- 로그인 안내 제목: **`그룹은 로그인 후 이용할 수 있어요`**
- 보조 설명: `로그인하고 함께 여행 기록을 모아보세요.`
- 계정 전환 설명은 버튼 아래 보조 문구로 유지한다: `처음 연결하는 계정은 지금 기록을 이어서 사용할 수 있어요. 이미 사용한 계정으로 로그인하면 해당 계정의 기록으로 전환돼요.`
- 복구·진행 중·실패 안내는 일반 로그인 설명과 구분해 해당 상태에서만 표시한다.

### 시각 규칙

- 화면 배경은 `pageBackground`, 카드 배경은 `surface`, 일반 테두리는 `border`를 사용한다.
- 제목·본문·보조 정보는 `headingText`, `bodyText`, `muted`와 `MaterialTheme.typography`를 조합한다. 앱 문구에는 공통 Line Seed KR 서체를 적용한다.
- 화면 좌우 여백 20dp, 카드 안쪽 여백 16dp, 주요 섹션 간격 24dp, 카드 간격 12dp, 작은 요소 간격 8dp를 기준으로 한다.
- 로그인 안내와 버튼 목록을 카드로 정리한다. 로딩·오류·복구 안내에도 같은 색과 간격 규칙을 적용한다.
- 카드 모서리는 기존 설정 카드와 `GroupTheme`의 medium 형태인 16dp에 맞춘다. 디자인 시스템 문서의 8/14/18/20dp 설명과 현재 구현이 다르므로 이번 변경에 사용하는 16dp 카드 규칙을 문서에도 명시한다. 앱 전체 모서리 변경은 범위에 포함하지 않는다.
- 그린/블루 × 라이트/다크 네 조합에서 강조 테두리와 작은 글씨 대비를 확인한다.
- 소셜 버튼의 최소 48dp 터치 영역과 제공자별 노출 조건, 클릭·분석 이벤트 연결을 유지한다.

## 4. ‘계정 확인 다시 시도’ 제거와 복구 동작

현재 이 버튼은 `session.restore()`를 다시 실행해 저장된 세션 및 `/members/me` 계정 조회를 재시도하는 역할이다. 그룹 화면에서는 로그인 안내가 보일 때 상시 노출되고, 설정에서는 계정 복원 실패 시 노출된다.

1. `GroupAccountRoute`와 `AccountSettingsPanel`의 `계정 확인 다시 시도` 버튼을 제거한다.
2. 설정에서 버튼만을 위한 `retry` 상태를 제거한다. 그룹의 `retry`는 그룹 탭 재선택과 목록 갱신에도 사용하므로 사용처를 확인하고 유지한다.
3. 화면 진입 시 기존 자동 복원을 유지한다. 실패 시 `계정 정보를 불러오지 못했어요. 연결 상태를 확인한 뒤 화면을 다시 열어 주세요.`처럼 실제 재시도 방법을 안내한다.
4. 그룹 탭 재선택/화면 재진입과 설정 화면 재진입으로 복원 가능한지 확인한다. 무한 자동 재시도나 recomposition마다 네트워크 요청을 추가하지 않는다.
5. `로그인 결과 확인` 버튼은 유지한다. 이 버튼은 중단된 계정 전환을 `resumeLogin()`으로 이어가는 별도 기능이며, 제거 요청 대상과 다르다.
6. 로그인 중 중복 클릭 방지, 기존 계정 재인증, 로그아웃 중 상태 처리를 보존한다. 계정 조회 실패를 정상 게스트 상태로 취급하지 않는다.

## 5. 설정 ‘내 정보’ 카드

설정 상단의 기존 `accountContent` 위치에 소셜 로그인 사용자에게만 카드를 표시한다.

```text
┌──────────────────────────────────┐
│ 내 정보                          │
│                                  │
│ 닉네임                 [프로필]  │
│ Google로 로그인         20 × 20  │
│                                  │
│ 로그아웃                         │
└──────────────────────────────────┘
```

- 사용자의 ‘왼쪽에 로그인 정보’ 요청을 기준으로 텍스트를 왼쪽, 이미지를 오른쪽에 배치한다.
- 로그인 정보는 현재 모델이 제공하는 닉네임과 제공자(`Google로 로그인`, `카카오로 로그인`, `Apple로 로그인`)로 구성한다. 이메일은 현재 모델에 없으므로 표시하지 않는다.
- 프로필 이미지는 **20dp × 20dp**, 원형 crop으로 표시한다. 긴 닉네임에도 이미지 크기를 유지하고 텍스트 영역이 남은 너비를 사용한다.
- 로딩 중·URL 없음·이미지 요청 실패 시 같은 크기의 기본 사용자 아이콘을 표시한다. 기존 공통 이미지 컴포넌트의 지원 범위를 확인하고 재사용한다.
- `surface` 배경, 1dp `border`, 16dp 모서리와 안쪽 여백을 적용하고 다음 설정 카드와 12dp 간격을 둔다.
- 로그아웃은 카드 안의 별도 액션으로 유지하며 기존 확인 다이얼로그와 처리 중 비활성화 조건을 보존한다.
- 게스트에게는 카드를 노출하지 않는다. 계정 조회 실패는 별도의 간결한 상태 안내로 표현하고, 로그인/로그아웃에 따른 카드 갱신을 확인한다.

### 프로필 사진 데이터 의존성

현재 `AccountMember`는 `nickname`, `provider`만 가지고, `AuthRemoteRepository.member()`는 `/members/me` 응답을 이 모델로 직접 읽는다. 따라서 **현재 클라이언트 데이터만으로 실제 프로필 사진을 표시할 수 없다.** 서버가 사진을 제공하는지는 이번 클라이언트 소스 점검만으로 확정하지 않는다.

구현 시작 시 서버 응답 계약을 확인한다. URL을 이미 제공하면 실제 필드명에 맞춰 nullable/default 값을 가진 프로필 이미지 필드를 연결한다. 제공하지 않으면 백엔드의 프로필 URL 제공 작업이 필요하다. URL 필드가 없거나 null인 기존 응답도 정상 처리해야 한다. 기본 아이콘만 구현한 상태를 실제 프로필 사진 연동 완료로 보고하지 않는다.

## 6. 변경 대상과 순서

아래 경로는 client 루트 기준이다.

| 순서 | 파일 | 작업 |
| --- | --- | --- |
| 1 | `shared/src/commonMain/kotlin/com/mapmory/shared/data/auth/AccountSession.kt`, `data/remote/AuthRemoteRepository.kt` | 실제 응답 계약 확인 후 프로필 데이터 연결; 두 번째 경로도 동일 Kotlin 패키지 루트 기준 |
| 2 | `shared/src/commonMain/kotlin/com/mapmory/shared/presentation/auth/SocialLoginPanel.kt` | 안내 문구, 카드 배치, 최근 로그인 말풍선/외곽 강조 |
| 3 | `shared/src/commonMain/kotlin/com/mapmory/shared/presentation/group/GroupAccountRoute.kt` | 화면 여백, 계정 재시도 버튼 제거, 실패 안내와 재진입 복구 확인 |
| 4 | `shared/src/commonMain/kotlin/com/mapmory/shared/presentation/auth/AccountSettingsPanel.kt` | 내 정보 카드, 20dp 이미지, 재시도 버튼 및 전용 상태 제거 |
| 5 | `shared/src/commonMain/kotlin/com/mapmory/shared/presentation/triprecord/screen/TripSettingsScreen.kt` | 필요 시 카드 사이 여백 정리 |
| 6 | `docs/design-system.md` | 사용한 카드 모서리 규칙과 브랜드 버튼 외곽 강조 예외 문서화 |

최근 로그인 장식은 필요하면 `presentation/auth` 아래 내부 컴포넌트로 분리한다. `SocialLoginButton` 본체는 브랜드 렌더링을 유지하고, 인증 컨트롤러의 상태 전환은 UI 정리를 위해 재설계하지 않는다.

## 7. 검증 및 완료 조건

- 네 가지 테마 조합에서 카드·말풍선·외곽선이 의미 색상을 따르며 작은 화면과 큰 글씨에서도 잘리지 않는다.
- 최근 로그인 없음/Google/카카오/Apple과 기기별 지원 제공자 조건에서 맞는 버튼만 강조된다.
- 그룹 로그인 화면에 새 문구가 표시되고 두 화면 어디에도 `계정 확인 다시 시도`가 남지 않는다.
- 네트워크 실패 후 화면 재진입 또는 그룹 탭 재선택으로 계정 조회가 복구된다. 중단된 로그인은 기존 `로그인 결과 확인` 또는 동일 제공자 재인증으로 계속할 수 있다.
- 소셜 로그인 사용자에게만 `내 정보` 카드가 표시되고, 왼쪽 정보와 오른쪽 20dp 이미지 배치가 유지된다.
- 프로필 URL 정상/없음/실패, 긴 닉네임, 로그인 후 진입, 앱 재실행, 로그아웃 후 카드 제거를 확인한다.
- 기존 로그인 분석 이벤트가 중복 발생하지 않는지 관련 JVM 테스트를 실행한다. 프로필 필드가 추가되면 필드 누락/null/정상 응답의 역직렬화를 검증한다.
- 구현 후 `:shared:jvmTest`, Android 빌드와 iOS 공통 코드 컴파일을 수행하고 실제 기기에서 로그인·설정 흐름과 시각 결과를 확인한다. 빌드 성공과 실기기 검증 결과는 구분해 기록한다.

현재 문서는 구현 계획이다. 기능 코드 변경, 빌드·테스트 및 실제 기기 확인은 아직 수행하지 않았다.
