# 그룹·앨범 운영 QA 점검 — 2026-10-29

## 사용자 확인에 따른 현재 범위 (2026-10-29)

아래 합의가 이 문서의 이전 권고보다 우선한다. 이전의 공개 전 권고는 검토 의견이며 승인된 구현 요구사항이 아니다.

- 한 멤버가 한 앨범에 여러 기록을 담는 현재 구현을 유지한다.
- 로그아웃·탈퇴 후에도 앱의 기본 사용이 가능하도록 새 게스트 사용을 허용한다. 회원 탈퇴 UI 자체는 아직 미구현이다.
- 기존 세션 처리와 영상 생성 상태의 2초 폴링은 유지한다. 폴링은 그룹 공유가 아닌 타임라인 영상 완료 확인이다.
- 그룹 나가기와 회원 탈퇴 연쇄, 원본 기록 삭제 시 기존 영상 처리 정책은 미결정이다. 이번 실행을 위해 임의로 구현하지 않는다.
- 사진 위치정보 제거, 탈퇴 시 영상·요청 정리와 피드백 작성자 정리, 기기 간 영상 목록은 이번 작업 범위에서 제외한다. 위험 해소나 구현 완료를 의미하지 않는다.
- 그룹/영상 푸시, 삭제 이벤트 구조·멱등 처리, 닉네임·업적·태그 구조 변경은 후속 작업으로 미룬다.
- 현재 목적은 기존 그룹·앨범 연결 및 리뷰 수정 버전을 연결된 휴대폰에서 실행하는 것이다.

## 결론과 검증 범위

현재 상태는 제한된 개발 QA를 진행할 수 있으나, 일반 사용자 공개 전 그룹 이탈·공유 철회·회원 탈퇴 후 노출 정책을 구현해야 한다. 앞서 수정한 화면 이동/복구/뒤로가기/열람 계측은 전체 운영 준비 완료를 뜻하지 않는다.

- 앱: `codex/group-api-live-studio`, HEAD `af0a6ab3` + 현재 미커밋 변경.
- 원격을 갱신해 확인한 서버: `backend-develop` `93ff007f33e6ed249ac3c7d15bd90b0d2151b49f`.
- `backend-release`는 `7cce6fb10efbb7d44323d15757609d46e57396e7`이며 AlbumController가 없다. 앱 기본 주소는 `https://api.map-mory.com/api/v1`이다. develop 병합과 운영 배포를 동일시하면 안 된다. 실제 운영 배포 SHA·DB 마이그레이션·인증된 앨범 요청은 이번에 확인하지 않았다.
- 기존 회귀 테스트 재실행: AlbumShareCoordinatorTest 8개, AlbumNavigationStateTest 2개, AlbumRemoteRepositoryTest 1개, 총 11개 통과.
- 이번 점검은 소스/기존 테스트/원격 브랜치/이슈 확인이다. 실제 계정 탈퇴나 서버 데이터 변경, 실기기·부하·네트워크 장애 주입 테스트는 실행하지 않았다.
- P1: 공개 전 해결 권고. P2: 운영 장애·혼란을 줄이기 위한 수정/정책 확정. 아래 영향 중 소스 분석으로 도출한 내용은 실기기 재현 완료를 뜻하지 않는다.

## 공개 전 우선 해결할 문제

### P1 — 회원 탈퇴 후에도 공유 기록이 다른 멤버에게 보이는 경로

`MemberService.withdraw`는 회원 익명화와 MemberWithdrawn 발행을 수행한다. 현재 이벤트 소비자는 refresh 토큰 폐기이며, 그룹·기록 정리는 연결되어 있지 않다. `AlbumQueryService.detailOf`는 기록 존재 여부만 확인하고, `TravelRecordQueryService.viewsOf`는 탈퇴한 소유자의 기록을 제외하지 않는다.

따라서 A가 공유 후 탈퇴해도 B가 같은 앨범을 조회하면 A의 기록·사진을 `탈퇴한 회원` 이름으로 계속 받을 수 있다. 멤버 행과 member_count도 남아 정원을 차지하고, 탈퇴한 방장도 자동 승계되지 않는다. 이 흐름은 소스 경로로 확인했으며 실제 두 계정 검증이 필요하다.

권고: 탈퇴 확정과 함께 타인에게 보여 주는 공유 연결 및 멤버십을 무효화하고, 방장 승계·빈 그룹 처리를 수행한다. 물리적 DB/S3 삭제는 명시한 기한 내 재처리 가능한 작업으로 수행한다. 단순 인메모리 AFTER_COMMIT 이벤트만으로 삭제 완료를 보장하지 않는다.

근거: [탈퇴 서비스](https://github.com/woowacourse-teams/2026-Mapmory/blob/93ff007f33e6ed249ac3c7d15bd90b0d2151b49f/backend/src/main/java/com/mapmory/backend/member/application/MemberService.java#L47), [앨범 조회](https://github.com/woowacourse-teams/2026-Mapmory/blob/93ff007f33e6ed249ac3c7d15bd90b0d2151b49f/backend/src/main/java/com/mapmory/backend/group/application/AlbumQueryService.java#L109), [기록 조회](https://github.com/woowacourse-teams/2026-Mapmory/blob/93ff007f33e6ed249ac3c7d15bd90b0d2151b49f/backend/src/main/java/com/mapmory/backend/travelrecord/application/TravelRecordQueryService.java#L58), [미완료 파기 이슈 #435](https://github.com/woowacourse-teams/2026-Mapmory/issues/435).

### P1 — 그룹 나가기·공유만 내리기·앱 회원 탈퇴 경로 부재

현재 GroupController는 생성/목록/상세/이름 수정, AlbumController는 목록/상세/생성/담기/수정만 제공한다. 앱의 Repository와 설정도 나가기·공유 해제·회원 탈퇴를 연결하지 않았고, 설정에는 로그아웃만 있다.

- 잘못 참여한 그룹에서 나가거나 특정 그룹에만 공유를 취소할 수 없다.
- 가입 그룹 한도 10개에 도달하면 사용자가 자리를 비울 방법이 없다.
- 개인 기록 삭제로 공유를 없애면 내 기록과 그 기록을 참조하는 다른 모든 앨범에도 영향을 준다. 이는 특정 그룹 공유 해제의 대체 수단이 아니다.

권고: 그룹 나가기와 내 기록의 앨범 연결 해제를 API부터 제공하고, 앱 확인 문구에 삭제되는 대상과 보존되는 대상을 명시한다. 계정 탈퇴는 아래 정책이 확정된 뒤 설정에서 연결한다.

근거: [그룹 API](https://github.com/woowacourse-teams/2026-Mapmory/blob/93ff007f33e6ed249ac3c7d15bd90b0d2151b49f/backend/src/main/java/com/mapmory/backend/group/web/GroupController.java), [앨범 API](https://github.com/woowacourse-teams/2026-Mapmory/blob/93ff007f33e6ed249ac3c7d15bd90b0d2151b49f/backend/src/main/java/com/mapmory/backend/group/web/AlbumController.java), 앱 `AccountSettingsPanel.kt`, `GroupRepository.kt`, `AlbumRepository.kt`.

### P1 — 배포 대상과 API 계약 일치 확인 필요

앨범 API가 develop에 병합되어 있지만 갱신된 release 브랜치에는 없다. 현재 앱은 live 계정에 앨범 영역을 표시한다. 운영 서버가 release 버전이면 해당 요청은 제공되지 않는다. 실제 운영 서버의 버전은 확인되지 않았다.

공개 전 운영 배포 SHA, V36의 앨범-기록 유니크 제약, `myTravelRecordIds`, 앨범 생성/담기/조회 응답을 같은 환경에서 확인해야 한다. 개발 QA는 앨범 API를 배포한 환경에서 진행한다.

추가 운영 주의:

- 새 앨범 생성은 서버 멱등성이 없다. 현재 ‘목록 확인 완료 · 작업 종료’는 사용자의 명시적 판단일 뿐, 서버 결과 대조 완료를 뜻하지 않는다. 이후 같은 기록으로 다시 만들면 중복될 수 있다.
- 초대는 1일 만료이며 새 초대 발급이 기존 초대를 폐기하지 않는다. 강퇴·초대 철회 API도 없다. 탈퇴한 발급자의 초대도 현재 검증은 토큰 만료와 그룹 존재 여부 중심이므로 유효기간 중 수락 경로가 남는다. 유출 대응 정책이 필요하다.
- 모든 그룹 멤버가 그룹 이름과 앨범 이름·지역을 바꿀 수 있다. 방장 전용 권한으로 이해하면 안 된다. 편집 이력/복구, 초대 가능 역할, 강퇴 제공 여부를 정해야 한다.
- 개인 기록은 복사본이 아닌 참조로 공유된다. 공유 후 개인 기록에 글·사진을 추가/수정하면 이를 참조하는 모든 앨범에 반영된다. 현재 편집 화면에 공유 범위 안내가 없어 사용자가 이를 모르고 사적인 사진을 추가할 수 있다. 공유 시와 편집 시 안내, 공유 대상 역조회가 필요하다.
- 회원 탈퇴 후 소셜 제공자 토큰 철회/연결 해제는 현재 서버 코드에 연결되지 않았다. ADR 0021에도 후속 작업으로 남아 있다. 서비스 탈퇴·제공자 연결 해제·DB/S3 파기를 별도 완료 조건으로 검증한다.

## 탈퇴·삭제 정책: 현재와 제안 구분

ADR 0021/0022의 상태 표기는 ‘제안’이다. 문서 내용이 모두 구현되었다고 간주하지 않는다. 특히 ADR 0022 본문의 ‘멤버당 기록 하나’는 문서 말미의 2026-10-28 보완으로 폐기되었고 서버는 여러 기록을 받는다.

| 행동 | 현재 구현 | 문서 방향 또는 이번 권고 |
|---|---|---|
| 로그아웃 | 이 기기 인증·캐시/작업 상태 정리, 서버 기록·그룹 유지 | 탈퇴와 구분해 안내. 미확인 공유는 계정별 복구 가능하도록 보완 |
| 그룹 나가기 | API/앱 미구현 | ADR: 그 그룹의 내 앨범 항목 모두 제거, 개인 기록 유지. 방장은 가장 먼저 들어온 잔여 멤버에게 승계. 마지막 멤버 이탈 시 그룹 삭제 |
| 내 기록 공유 내리기 | API/앱 미구현 | ADR: 선택한 앨범과 연결만 제거. 원본과 다른 앨범 연결은 유지 |

| 개인 기록 삭제 | 원본 DB 기록 삭제. 앨범 조회는 사라진 기록을 응답에서 제외 | 모든 앨범 연결 정리·빈 앨범 삭제·표지/개설자/정렬 갱신을 연쇄 처리. 현재는 T7 미구현 |
| 회원 탈퇴 | `DELETE /members/me`: soft 탈퇴, 이름/닉네임 익명화, provider_id 비움, refresh 전체 폐기. 반복 요청은 204. 앱 UI 없음 | 모든 그룹의 공유 연결/멤버십 제거·방장 승계와 실제 파기 작업 연결 필요 |
| 탈퇴 후 같은 소셜 계정 재가입 | 새 회원 ID. 이전 기록·그룹 자동 복원 없음. 재가입 유예 없음 | 사용자에게 명시하고, 소셜 제공자 연결 상태도 검증 |
| 탈퇴 후 사진·기록 파기 | 기한과 소비자 미구현, #435 OPEN | 즉시 노출 차단과 물리적 파기를 구분. 파기 기한·재시도·실패 알림·완료 판정 결정 |
| 이미 발급한 사진 URL/기기 캐시 | 회원 권한과 별개로 유효기간 동안 이용되거나 이미 표시된 내용이 남을 수 있음 | ‘즉시 모든 사본 삭제’라고 안내하지 않는다. 서버의 새 URL 발급 차단, 앱 캐시 제거, URL/CDN 만료 정책을 함께 검증 |

회원 탈퇴 토큰 주의: refresh는 폐기되지만 이미 발급된 access token은 최대 30분 남는다. 최신 서버는 회원 API·그룹 API·기록 생성·업로드 URL 발급·영상 생성에서 활동 상태를 확인한다. 기록 수정 등 모든 경로가 동일하게 차단되는 것은 아니다. 현재 ADR는 파기를 이 잔여 시간 이후에 시작하도록 기술한다. 즉시 파기를 채택하려면 남은 접근/쓰기 경로도 먼저 닫아야 한다.

## 권장 처리 순서

1. 서버·앱 담당자가 나가기/공유 해제/회원 탈퇴의 노출·원본 보존·정원·방장·빈 앨범·초대 무효화 정책을 확정한다.
2. 그룹 나가기/연결 해제/탈퇴 연쇄 및 파기 작업을 구현하고 배포 환경을 맞춘다.
3. 앱의 계정별 미확인 작업 보존, 오류별 복구, 접근 불가 시 상세 제거, 저장소 복구를 보완한다.
4. Q01~Q30을 실제 두 플랫폼/두 계정으로 실행하고 결과·서버 요청 ID·앱 로그를 남긴다. 이벤트에는 원본 식별자를 추가하지 않는다.
5. 실패율/미확인 작업 잔존 시간/탈퇴 파기 실패 수/앨범 응답 지연과 크기를 모니터링한다. 공유 성공 건수의 최종 기준은 서버 데이터로 둔다.
