# Mapmory AI 보조 QA

AI가 테스트를 대신 결정하는 것이 아니라, 합의된 기대 결과를 실제 앱에서 확인하고 근거를 정리하는 절차다. 사람은 기대 결과와 최종 판정을 맡고, AI는 테스트 계획, 실행 보조, 관찰, 결과 정리를 맡는다.

## 진행 순서

1. **범위와 기준 확인**: 대상 PR/커밋과 승인된 요구사항, 수용 기준을 확인한다. 코드나 오래된 문서만 보고 기대 동작을 새로 만들지 않는다. 자료끼리 충돌하거나 결과가 불명확하면 해당 케이스를 `확인 필요`로 두고 사람에게 기준을 확인한다.
2. **환경 기록**: 커밋 SHA, 앱 빌드/버전, Android 또는 iOS, 기기/OS 버전, 로그인·데이터 상태, 권한, 네트워크 상태를 기록한다. 운영 계정이나 실제 사용자 데이터로 테스트하지 않는다.
3. **케이스를 작게 나눔**: 한 케이스는 하나의 사용자 행동과 검증 가능한 기대 결과를 갖게 한다. 사전 조건, 행동, 기대 결과를 실행 전에 적고, 케이스 ID마다 결과가 빠짐없이 남았는지 마지막에 대조한다.
4. **기존 검증부터 실행**: 변경 범위에 맞는 기존 단위 테스트, 정적 검사, 빌드와 CI를 우선 사용한다. 기기 확인은 기존 UI 테스트나 접근성 정보와 테스트 식별자를 먼저 활용하고, 필요할 때 화면 캡처·녹화·로그를 보조 증거로 쓴다.
5. **플랫폼별로 관찰**: Android 결과를 iOS 결과로 간주하지 않는다. 변경된 호출 경로와 동작이 있는 플랫폼을 각각 확인한다. 일시적인 스낵바·토스트처럼 화면 캡처 전에 사라지는 결과는 동작 전후 녹화나 로그로 확인한다.
6. **증거와 함께 보고**: 실제 관찰이 기대 결과를 뒷받침할 때만 통과로 표시한다. 근거 파일은 Git 변경물에 넣지 않고 `.omx/outputs/ai-qa/<실행 ID>/`에 둔다.

## 실행 범위

| 모드 | 확인 범위 | 결과물 |
| --- | --- | --- |
| 빠른 확인 | 변경된 사용자 흐름과 바로 인접한 회귀 케이스 | 짧은 결과표, 실패나 불확실 케이스의 증거 |
| 전체 확인 | 기능의 주요 흐름과 변경으로 영향받는 권한, 네트워크, 생명주기, Android/iOS 예외 흐름 | 전체 케이스 결과표, 재현 절차, 필요한 화면·로그 증거 |

테스트할 예외 조건은 변경 영향에 맞춰 고른다. 모든 기능에 무관한 예외 테스트를 기계적으로 추가하지 않는다. 클라이언트 CI의 현재 명령과 범위는 [CI 문서](../ci.md), 기능별 자동화 예시는 [사진 메타데이터 테스트](photo-metadata-automation.md)를 따른다.

## 스프린트 회귀 점검

먼저 기록 손실, 중복 생성, 잘못된 인증 처리처럼 사용자가 복구하기 어려운 문제를 확인한다. 다음 표는 자동 테스트 통과 여부와 별개로 기기에서 확인할 후보이며, 승인된 요구사항이 없는 항목은 `확인 필요`로 둔다.

| 흐름 | 나눠서 확인할 조건 | 관찰할 결과 |
| --- | --- | --- |
| 사진 고르기 | 0장, 1장, 최대 허용 장수, 초과 시도, 선택 후 원본 삭제, 제한된 사진 권한 | 다음 단계 가능 여부, 선택 수와 실제 저장 사진 일치, 누락 안내 |
| 기록 저장 | 앱 사용 중, 홈으로 이동, 복귀 직전/직후 완료, 화면 잠금, 중복 탭 | 기록 한 번 저장, 진행 종료, 현재 앱 상태에 맞는 완료 안내, 안내를 누르면 해당 일지 이동 |
| 영상 만들기 | 서로 다른 국가 0/1/2개, 요청 연타, 생성 중 닫기/다시 열기, 상태 조회만 실패 | 생성 조건 일치, 기존 jobId 유지, 상태 조회 실패로 새 생성 요청을 보내지 않음 |
| 영상 완료/중단 | 다운로드 실패, URL 만료, 이전 작업의 늦은 응답, 앱 재실행 | 재시도 가능, 새 작업을 이전 응답이 덮어쓰지 않음. 서버 취소와 로컬 추적 중단을 구분 |
| 권한/인증 | 첫 거절, 재요청 불가, 설정에서 허용/철회 후 복귀, 만료 코드와 다른 401 | 기능 재진입 시 복구 경로, 불필요한 refresh/무한 로딩 없음 |
| 화면 | 밝은/어두운 테마, 지원하는 각 색상 테마, 큰 글자, 작은 화면, iOS 안전 영역 | 글자와 배경 대비, 버튼 잘림/겹침, 상하 배경 단절 없음 |

생명주기 케이스는 `요청 → 백그라운드 → 완료 → 복귀`와 `요청 → 백그라운드 → 복귀 → 완료`를 따로 실행한다. 앱 프로세스 종료는 단순 백그라운드 이동과 구분하고, OS가 종료한 경우와 사용자가 강제 종료한 경우를 동일한 동작으로 가정하지 않는다.

재현 기록에는 빈도(예: 3회 중 2회), 영향받는 데이터, 기대/실제 결과, 직전 상태 전환을 적는다. 기록 손실·중복·진입 불가는 우선 수정하고, 시각적 문제는 읽기/조작 방해 여부로 우선순위를 정한다. 스크린샷 렌더 성공이나 컴파일 성공만으로 기기 동작·접근성·대비를 통과 처리하지 않는다.

### 디자인 확인 기준

디자인 시안과 실제 화면을 같은 크기·테마에서 비교한다. 폰트 크기/두께/행간, 색상 토큰, 간격과 정렬, 로딩·빈 목록·오류 상태, 긴 텍스트, 화면 크기, 시스템 글자 크기와 테마, 이미지 방향과 비율을 각각 확인한다. 값 비교와 실제 읽기·조작 확인을 함께 남긴다.

참고: [QA실무노트 디자인 QA 게시물](https://www.instagram.com/qaonetop/reel/DfYE8gjSH5s/)의 화면에 제시된 점검 축을 맵모리 흐름에 맞게 구체화했다. [테스트 케이스 작성 게시물](https://www.instagram.com/qaonetop/reel/DfMNII7xTj5/)에서는 케이스 식별자와 사전 조건 구성을 확인했다. 위 회귀 표의 기대 동작은 해당 계정의 정책이 아니라 맵모리 요구사항과 현재 구현을 검토하기 위한 기준이다.

## 알림, 외부 진입과 데이터 갱신 점검

아래는 QA실무노트 프로필에서 확인한 푸시, 딥링크, 캐시, API 오류, 결함 생명주기 주제를 맵모리에 적용한 점검 항목이다. 게시물 영상 전체를 분석한 결과나 해당 계정의 구체적인 지침을 옮긴 것은 아니다. 각 케이스는 Android/iOS에 별도 결과를 남기고, 구현되지 않은 기능은 요구사항 확인 전까지 실패로 단정하지 않는다.

| ID | 사전 조건과 행동 | 기대 결과 / 확인 기준 |
| --- | --- | --- |
| PUSH-01 | 영상 완료 직전 앱을 전경, 배경, 종료 상태로 각각 전환 | 전경은 화면 내 안내, 배경은 권한과 기능 설정에 따른 알림. OS 종료와 사용자 강제 종료는 별도 기록 |
| PUSH-02 | 같은 완료 이벤트를 재수신하고 알림을 여러 번 누름 | 중복 안내·화면 적층 없이 해당 jobId 상태 확인. 다른 영상으로 이동하지 않음 |
| PUSH-03 | 권한 철회, 알림 설정 해제, 토큰 등록 실패 후 영상 생성 | 영상 생성 가능, 알림 불가 안내와 복구 경로 제공. 복귀 시 등록/해제 재시도 여부 확인 |
| ENTRY-01 | 앱이 꺼진 상태와 실행 중인 상태에서 완료 알림 누름 | 해당 영상 미리보기로 이동. 로그인 필요 시 진입 의도를 보존하되 다른 계정의 영상은 노출하지 않음 |
| ENTRY-02 | 없는 jobId, 잘못된 값, 다운로드 URL 만료, 오프라인에서 진입 | 크래시·무한 로딩 없이 오류/재시도 제공. 만료 URL은 재발급 경로 확인 |
| CACHE-01 | 기록 수정·사진 교체·삭제 후 목록, 상세, 지도, 통계로 재진입 | 현재 서버 데이터와 표시가 일치. 새로고침/앱 재시작 전후를 나누어 캐시 문제 구분 |
| CACHE-02 | 로그아웃 후 다른 테스트 계정 로그인 | 이전 계정 사진, 영상, 작업 상태, 알림 목적지가 새 계정에 노출되지 않음 |
| API-01 | 같은 화면에서 정상 응답, 업무 오류 코드, 통신 실패를 각각 재현 | HTTP 상태와 업무 코드를 함께 기록. EXPIRED_ACCESS_TOKEN 외 오류로 불필요한 refresh를 보내지 않음 |

푸시는 `서버 작업 완료 → 발송 → 기기 수신 → 표시 → 탭 → 목적지`를 따로 판정한다. 로컬 알림 주입이나 미리보기만 통과한 결과를 실제 FCM 전달 성공으로 보고하지 않는다. 인증·FCM 토큰, 서명된 URL, 실제 사용자 사진은 증거에 넣지 않는다.

참고 주제: [푸시 알림](https://www.instagram.com/qaonetop/reel/DfeNMdbR5qP/), [딥링크](https://www.instagram.com/qaonetop/reel/DfdwkEkxism/), [캐시](https://www.instagram.com/qaonetop/reel/Dff4rWIypo8/), [API 오류](https://www.instagram.com/qaonetop/reel/Dfbygvfu0vw/), [결함 생명주기](https://www.instagram.com/qaonetop/reel/DfenliuB6rH/).

결함은 발견으로 끝내지 않는다. 재현 케이스 ID, 영향 플랫폼, 담당 수정/PR, 수정 빌드, 재검증 결과와 인접 회귀 결과를 연결한다. 재현 불가·환경 차단·기준 미합의는 해결 완료와 구분하고, 완료 처리에는 같은 재현 절차로 문제가 사라졌다는 증거를 남긴다.

## 결과 상태

| 상태 | 의미 |
| --- | --- |
| `통과` | 행동을 실행했고, 기대 결과를 직접 관찰해 증거를 남김 |
| `실패` | 행동을 실행했고, 기대 결과와 다른 동작을 재현함 |
| `차단` | 기기·빌드·서버·네트워크 등 테스트 환경 문제로 실행할 수 없음 |
| `미실행` | 범위에는 있으나 이번 실행에서 수행하지 않음 |
| `확인 필요` | 실행은 했지만 관찰이 부족하거나, 요구사항/기대 결과가 모호함 |

환경 문제나 모호한 기준을 앱 결함으로 단정하지 않는다. 실행하지 않았거나 결과를 확인하지 못한 케이스를 통과로 보고하지 않는다. AI는 이 절차에서 앱 코드를 자동 수정하거나 커밋하지 않는다. 수정이 필요하면 발견 내용과 재현 증거를 먼저 정리하고 별도 요청에 따라 고친다.
