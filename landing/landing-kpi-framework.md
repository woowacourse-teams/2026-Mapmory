# Mapmory 랜딩페이지 Lean 검증안

이 문서는 이전 랜딩과 리팩터링 랜딩 중 어느 쪽이 Mapmory의 가치를 더 잘
전달하고 출시 알림 신청으로 이어지는지 판정합니다. 외부 평균 전환율을 성공
기준으로 복사하지 않고, Unbounce가 제시한 전환 원리를 Mapmory에서 관찰할 수
있는 행동으로 바꿉니다.

- 작성일: 2026-08-26
- 비교 대상: 이전 랜딩(Control)과 에디토리얼 랜딩(Variant)
- 현재 최종 전환: 신규 출시 알림 신청
- 출시 후 최종 전환: 앱 설치와 첫 기억 지도 생성

## 이번 검증이 답할 질문

이번 검증은 한 가지 결정만 지원합니다.

> 실제 제품 흐름을 먼저 체험시키는 새 랜딩이 이전 랜딩보다 신규 출시 알림
> 신청을 늘리는가? 늘어난다면 사용자가 Mapmory의 가치를 이해하고 기억을 직접
> 열어본 결과인가?

검증할 경로는 다음과 같습니다.

`가치 이해 → 지구본 체험 → 장소 기억 열기 → 출시 알림 신청`

스크롤 깊이, 체류 시간, 지구본 회전 횟수는 단독 성공 지표로 사용하지 않습니다.
이러한 행동은 장소 기억 열기나 출시 알림 신청의 변화를 설명할 때만 확인합니다.

## Unbounce 문구를 Mapmory 지표로 번역하기

[Unbounce의 랜딩페이지 전환율 안내](https://unbounce.com/average-conversion-rates-landing-pages/)
는 전환을 `전환 수 ÷ 방문자 수`로 정의하고, 개선 요인으로 명확한 가치 제안,
집중된 CTA, 마찰 제거, 모바일 대응, 속도, 반복 테스트를 제시합니다. Mapmory는
각 원리를 다음처럼 검증합니다.

| Unbounce의 원리 | Mapmory에서 확인할 내용 | 측정 방법 |
| --- | --- | --- |
| 가치 제안 명확화 | 첫 화면만 보고 장소 기반 기억 지도라고 이해하는가 | 5초 이해도 테스트 |
| 방해 요소 최소화 | 사용자가 다음 행동을 망설이지 않는가 | CTA 약속 이행률 |
| 명확한 CTA | `지구본 돌려보기`가 실제 기억 열기로 이어지는가 | CTA 이후 `memory_open(open_index=1)` |
| 마찰 제거 | 관심 있는 사용자가 폼에서 이탈하지 않는가 | 폼 완료율과 오류 원인 |
| 모바일 대응 | 모바일에서 핵심 체험이 약해지지 않는가 | 모바일·데스크톱 체험률 차이 |
| 속도 | 첫 화면과 지구본이 충분히 빠르게 반응하는가 | Core Web Vitals 릴리스 기준 |
| 반복 테스트 | 새 문구와 구조가 실제로 더 나은가 | 동일 기간 A/B 비교 |

Unbounce가 언급한 소셜 증거와 긴급성은 현재 핵심 지표에 넣지 않습니다. 실제
후기나 진짜 기한이 없는 상태에서 이를 추가하면 Mapmory의 신뢰와 제품 범위를
왜곡할 수 있습니다.

## 이전 문구와 새 문구에 대한 가설

이전 첫 화면은 여러 사용 사례와 두 개의 행동을 동시에 제시했습니다.

- 이전 헤드라인: `다녀온 곳이 쌓일수록, 나만의 기억 지도가 완성돼요.`
- 이전 설명: 여행, 데이트, 카페, 라멘 등 여러 사례를 한 번에 소개
- 이전 행동: `출시 알림 신청하기`와 `설치 전에 먼저 체험하기`

새 첫 화면은 감정적 약속, 제품 설명, 체험 행동을 한 줄씩 분리했습니다.

- 새 헤드라인: `장소를 따라가면, 그날의 기억이 다시 열려요.`
- 새 설명: `사진과 장소를 모아 나만의 기억 지도를 만들어요.`
- 새 주요 행동: `지구본 돌려보기`
- 새 보조 행동: `출시 알림 신청하기`

새 문구는 더 짧고 주요 행동이 하나라서 Unbounce의 가치 제안과 CTA 원칙에 더
가깝습니다. 다만 출시 알림을 보조 행동으로 내렸으므로, Hero CTA 클릭률만으로
성공을 선언하면 안 됩니다. 최종 신규 신청률이 유지되거나 올라야 하며, 그
사이에 실제 장소 기억 열기가 증가해야 합니다.

## 최소 측정 지표

운영 점수판에는 결과 지표 1개, 원인 지표 3개, 가드레일 2개만 둡니다.

### 결과 지표: 신규 출시 알림 전환율

이 지표는 출시 전 랜딩의 최종 성과를 측정합니다.

```text
신규 출시 알림 전환율 =
waitlist_submit(result = subscribed) 고유 사용자 수
÷ 유효 랜딩 방문 고유 사용자 수
```

`already_subscribed`, 팀원, QA, 봇 트래픽은 신규 전환과 분모에서 제외합니다.

### 원인 지표 1: 핵심 체험 완료율

이 지표는 체험 섹션을 본 사용자가 실제로 다른 기억을 열었는지 측정합니다.

```text
핵심 체험 완료율 =
memory_open(experience_type = globe, open_index = 1) 고유 사용자 수
÷ experience_view(experience_type = globe) 고유 사용자 수
```

전체 방문자를 분모로 쓰지 않습니다. 그래야 첫 화면에서 체험 섹션까지의 도달
문제와 지구본 자체의 사용성 문제를 구분할 수 있습니다.

새 CTA 문구가 약속한 행동까지 이어지는지는 같은 지표를 다음처럼 잘라서
진단합니다.

```text
CTA 약속 이행률 =
experience_cta_click(cta_placement = hero) 이후 같은 세션에서
memory_open(experience_type = globe, open_index = 1)을 한 고유 사용자 수
÷ experience_cta_click(cta_placement = hero) 고유 사용자 수
```

이 수치는 새 안의 CTA 진단용이며 이전안과 직접 비교하지 않습니다. 이전 Hero의
체험 CTA에는 같은 클릭 이벤트가 없기 때문입니다.

### 원인 지표 2: 기억 탐색 깊이와 정확한 체험시간

`memory_open`은 같은 체험에서 같은 기억을 한 번만 기록하며 `open_index`로 첫째,
둘째, 셋째 고유 기억을 구분합니다. `experience_end`는 체험 영역이 화면에 보이고
브라우저 탭이 활성화된 시간만 `active_duration_ms`에 누적합니다.

```text
체험당 고유 기억 수 =
experience_end.unique_memories_opened

정확한 활성 체험시간 =
experience_end.active_duration_ms

첫 가치 도달시간 =
memory_open(open_index = 1).time_since_start_ms
```

체험시간은 단독 성공 지표로 사용하지 않습니다. `기억 0개 + 긴 체험`은 혼란일
수 있고 `기억 2개 이상 + 긴 체험`은 자발적 탐색일 수 있으므로 기억 개수와 신청
결과로 나눠서 봅니다. 10·30·60초 마일스톤 이벤트 대신 각 사용자의 실제 시간을
숫자형 맞춤 측정항목으로 분석합니다.

### 원인 지표 3: 체험 후 신청 의도율

이 지표는 장소 기억을 연 경험이 출시 알림 신청 의도로 이어졌는지 측정합니다.

```text
체험 후 신청 의도율 =
memory_open 이후 같은 세션에서 waitlist_form_start를 한 고유 사용자 수
÷ memory_open을 한 고유 사용자 수
```

GA4 탐색 보고서 또는 PostHog의 순서 고정 Funnel에서 계산합니다. 반복 점검은 `POSTHOG_DASHBOARD_SETUP.md`의 운영 대시보드를 사용합니다.

### 단계별 이탈률

별도의 이탈 이벤트는 만들지 않습니다. 같은 세션의 닫힌 순차 퍼널에서 다음
단계가 없는 사용자를 이탈로 계산합니다.

```text
page_view
→ experience_cta_click 또는 experience_view
→ experience_start
→ memory_open(open_index = 1)
→ memory_open(open_index = 2)
→ waitlist_form_view
→ waitlist_form_start
→ waitlist_submit_attempt
→ generate_lead

단계 이탈률 =
1 - 다음 단계 사용자 수 ÷ 현재 단계 사용자 수
```

CTA를 누르지 않고 직접 스크롤한 방문자는 `experience_view`부터 퍼널에 들어옵니다.
각 단계는 `landing_version`, 기기 유형, 유입 소스로 나눠 비교합니다.

### 가드레일 1: 폼 완료율

이 지표는 실제 관심이 폼 마찰 때문에 손실되는지 확인합니다.

```text
폼 완료율 =
waitlist_submit(result = subscribed | already_subscribed) 고유 사용자 수
÷ waitlist_submit_attempt 고유 사용자 수
```

`waitlist_submit_error`는 KPI가 아니라 원인 진단에 사용합니다. 검증 오류는
`validation_field`로, 네트워크와 서버 오류는 `error_type`으로 나눕니다.

### 가드레일 2: 모바일 핵심 체험 격차

이 지표는 모바일 경험이 데스크톱보다 구조적으로 불리한지 확인합니다.

```text
모바일 핵심 체험 격차 =
모바일 핵심 체험 완료율 ÷ 데스크톱 핵심 체험 완료율 - 1
```

모바일 수치가 데스크톱보다 20% 이상 낮으면 새 안의 승패와 별개로 모바일
상호작용을 점검합니다. 속도는 전환 KPI에 섞지 않고 릴리스 기준으로 관리합니다.
Core Web Vitals의 75번째 백분위에서 LCP 2.5초 이하, INP 200밀리초 이하,
CLS 0.1 이하를 통과해야 합니다.

## 문구 이해도 사전 검증

트래픽을 받기 전에 처음 보는 사용자 5명으로 짧게 검증합니다. 숫자 분석으로는
문구를 오해했는지 알 수 없으므로 이 단계가 먼저입니다.

1. 첫 화면을 5초 동안 보여준 뒤 `이 서비스는 무엇을 하는 것 같나요?`라고
   묻습니다.
2. 화면을 다시 보여주고 `다음에 무엇을 할 수 있을 것 같나요?`라고 묻습니다.
3. 아무 안내 없이 장소 기억 하나를 열어 달라고 요청합니다.

다음 표현을 그대로 말할 필요는 없지만, 첫 답변에 `장소 또는 지도`와
`기억 또는 사진 기록`의 의미가 모두 포함되어야 가치 이해로 인정합니다.

| 결과 | 판정 |
| --- | --- |
| 5명 중 4명 이상이 가치와 다음 행동을 이해하고 기억을 엶 | 통과 |
| 5명 중 3명이 성공 | 문구 또는 안내 한 차례 수정 후 재검증 |
| 5명 중 2명 이하가 성공 | 첫 화면 가설 실패 |

이 기준은 업계 평균이 아니라 빠른 사용성 판정을 위한 내부 운영 규칙입니다.

## 이전안과 새 안의 판정 규칙

가능하면 두 안을 같은 기간과 같은 유입 소스에서 무작위로 노출합니다.
`landing_version`은 Control과 Variant를 구분해야 합니다.

| 판정 | 조건 |
| --- | --- |
| 성공 | 새 안의 신규 전환율이 이전안보다 상대 20% 이상 높고, 차이의 95% 신뢰구간이 0을 넘으며, 두 가드레일이 악화되지 않음 |
| 실패 | 새 안의 신규 전환율이 통계적으로 유의하게 낮거나, 문구 이해도 테스트가 2명 이하임 |
| 보류 | 전환 차이의 신뢰구간이 0을 포함하거나 표본이 부족함 |

20%는 업계 벤치마크가 아니라 디자인 교체를 정당화할 최소 실질 개선폭입니다.
기존 전환율을 확인한 뒤 필요한 표본 수를 계산하고, 최소 14일 동안 실험해
요일 효과를 포함합니다. A/B 노출이 불가능하면 유입 소스와 기기 구성이 비슷한
연속 14일 구간을 비교하되, 결과를 인과 효과가 아닌 방향성으로만 해석합니다.

## 현재 이벤트로 가능한 것과 부족한 것

현재 구현은 같은 허용 이벤트를 GA4와 PostHog에 보내므로 신규 전환, 체험 완료,
고유 기억 탐색 수, 정확한 활성 체험시간, 단계별 이탈, 폼 완료를 계산할 수
있습니다. GA4는 유입·최종 전환, PostHog은 반복해서 보는 체험 대시보드에
사용합니다. 분석할 때 다음 제한을 적용합니다.

- Hero CTA와 스크롤 유도는 `experience_cta_click`으로, 실제 첫 조작은
  `experience_start`로 분리됩니다.
- `memory_open`은 선택 모션 이후 별도 기억 패널이 실제로 열린 시점에 기록되며,
  같은 체험에서 같은 기억의 반복 열기는 고유 기억 수에 중복하지 않습니다.
- `experience_end.active_duration_ms`는 체험 영역이 보이고 탭이 활성화된 시간만
  누적하며, 첫 연속 체험이 끝날 때 체험 유형별 한 번 기록합니다.
- 페이지 종료 이벤트는 브라우저 상황에 따라 전송이 누락될 수 있으므로
  `section_exit` 표본을 함께 보고 GA4 전체 페이지 참여시간으로 결측을 점검합니다.
- `waitlist_submit_attempt`는 클라이언트 검증 전 모든 제출 시도를 기록합니다.
- 현재 새 랜딩 기본 버전은 `v2`이며 자동 `page_view`에도 포함됩니다.
- Core Web Vitals의 실제 사용자 측정은 아직 현재 이벤트 목록에 없습니다.

대한민국 기억 추가와 정확한 체험시간은 상위 결과 KPI가 아닙니다. 기억을 열지
못한 사용자와 여러 기억을 연 사용자, 신규 신청자를 나눠 이탈 원인을 진단합니다.

## 검증 순서

측정은 다음 순서로 진행합니다.

1. 처음 보는 사용자 5명으로 문구 이해도와 CTA 발견성을 확인합니다.
2. Control과 Variant에 서로 다른 `landing_version`을 설정합니다.
3. 같은 유입을 무작위로 나누고 모바일, 데스크톱, 유입 소스를 함께 기록합니다.
4. 결과 지표 1개, 원인 지표 3개, 가드레일 2개만 주간으로 확인합니다.
5. 최소 14일과 계산된 표본 수를 모두 충족한 뒤 성공, 실패, 보류를 판정합니다.
6. 보류이면 지표를 추가하지 않고 실험 기간을 늘리거나 더 큰 문구 차이를
   테스트합니다.

## 근거와 적용 한계

Unbounce의 6.6%는 41,000개 랜딩페이지, 4억 6,400만 방문, 5,700만 전환을
기반으로 한 전체 산업 중앙값입니다. 같은 글은 전환의 정의와 페이지 목표,
산업에 따라 좋은 수치가 달라진다고 명시합니다. 따라서 이 숫자는 Mapmory의
성공선으로 사용하지 않습니다.

- [Unbounce 전체 랜딩페이지 전환율과 개선 원리](https://unbounce.com/average-conversion-rates-landing-pages/)
- [Unbounce 벤치마크 방법론](https://unbounce.com/conversion-benchmark-report/methodology/)
- [Google Core Web Vitals 기준](https://web.dev/articles/vitals)

Mapmory의 성공선은 외부 평균이 아니라 이전안 대비 실질 개선, 문구 이해,
제품 체험, 폼 품질을 함께 만족하는지로 결정합니다.
