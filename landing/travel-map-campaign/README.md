# Mapmory Travel Map 웹 캠페인

사진의 촬영 날짜와 GPS를 이용해 여행 지도를 재생하고, 9:16 영상 또는 지도 이미지로 저장하는 독립적인 Vite/React 웹 프로토타입입니다. Mapmory 앱 유입을 위한 캠페인이며, 이 영상 생성 기능이 현재 앱에도 제공된다고 안내하지 않습니다.

## 주요 흐름

1. 여러 사진을 선택하거나 팀 사진으로 구성된 샘플을 실행합니다.
2. 브라우저에서 EXIF/XMP 날짜와 GPS를 분석합니다. 좌표를 읽지 못한 파일은 별도 진단 결과로 표시합니다.
3. 촬영 시각순으로 연결된 지도 경로를 재생합니다.
4. 같은 재생 데이터를 9:16 미리보기, 영상 저장/공유, PNG 저장에 사용합니다.
5. 앱 다운로드와 Mapmory 소개 페이지를 별도 CTA로 제공합니다.

원본 사진은 서버에 업로드하지 않습니다. 사진 분석과 영상 생성은 브라우저에서 수행하며, 설정된 분석 도구에는 캠페인 단계·사진 장수·결과 형식 등의 이벤트를 보냅니다. 사진 파일명과 GPS 좌표는 이벤트로 전송하지 않습니다.

## 실행 및 검증

CI와 동일한 Node.js 24 환경을 사용합니다.

```sh
cd landing/travel-map-campaign
npm ci
npm run dev
```

일반 `npm test`는 테스트에 필요한 루트/Sites 및 Recap 산출물을 먼저 빌드합니다. `npm run test:sites`도 Sites 빌드 후 실행합니다. CI처럼 같은 환경에서 빌드를 이미 완료했다면 `npm run test:built`로 재빌드 없이 전체 테스트를 실행할 수 있습니다.

개발 서버와 빌드 미리보기(`npm run preview`)는 모두 `http://127.0.0.1:4174/`를 사용합니다. 동시에 실행하지 않으며, 포트가 이미 사용 중이면 다른 포트로 넘어가지 않고 종료합니다. 기존 서버의 작업 경로를 확인해 재사용하거나 해당 캠페인 서버만 종료한 뒤 교체합니다. 다른 작업의 서버를 종료하거나 충돌을 피해 새 포트를 계속 열지 않습니다. 기본 접속은 이 PC로 제한하며 휴대폰 LAN 테스트가 필요한 경우에만 명시적으로 범위를 변경합니다.

배포 산출물을 포함한 검증은 다음 순서로 실행합니다. 테스트 명령이 필요한 빌드를 먼저 준비하므로 새 체크아웃에서도 같은 명령을 사용합니다.

```sh
npm test
# Sites 호환 패키징만 별도로 확인할 때
npm run test:sites
```

`Landing CI`에서 이 패키지를 상위 랜딩과 별도의 작업으로 설치·빌드·테스트합니다. 테스트에는 좌표 형식 처리, 대표 사진 묶음, 통계 보존, 재생 타이밍, CTA 대상/이벤트, 정적 파일 제공과 SPA fallback 검증이 포함됩니다.

`npm run build`는 기존 루트/Sites용 `dist/client`와 운영 하위 경로용 `dist/recap`을 각각 만듭니다. 운영 출력만 빌드하려면 `npm run build:recap`, 운영 경로를 확인하려면 기존 서버를 종료한 뒤 `npm run preview:recap`으로 `http://127.0.0.1:4174/recap/`에 접속합니다. 추가 포트는 사용하지 않습니다.

### 의존성 보안 검증

- 2026-09-03 의존성 패치: Vite 6.4.3, PostCSS 8.5.26, Browserslist 4.28.8, Nano ID 3.3.18. 기존 메이저 버전과 앱 동작은 유지합니다.
- `npm audit`로 현재 레지스트리의 취약점 보고를 확인합니다. 0건은 알려진 의존성 경고가 없다는 뜻이며 전체 서비스의 안전을 보장하지 않습니다.
- `tests/dependency-security.test.mjs`는 잠금 파일의 보안 패치 하한, PostCSS 소스맵 경로 제한, Browserslist 비정상 통계 처리, Nano ID의 ESM/CJS 종료 조건과 Vite 파일 접근 제어를 검사합니다. Windows ADS/짧은 이름 검사는 Windows에서만 실행합니다.
- 테스트는 가짜 소스맵만 사용하며 실제 비밀 파일, UNC/SMB 인증 요청이나 메모리 고갈 공격을 실행하지 않습니다. UNC 차단과 캐시 상한은 패치 소스 및 의존성 감사로 확인합니다.

## 대표 사진과 재생 규칙

- 촬영 간격이 72시간을 초과하면 새로운 여행으로 구분하는 초기 휴리스틱을 사용합니다.
- 같은 여행의 시간순 연속 사진이 묶음의 첫 좌표로부터 50m 이내이고 직전 사진과 60분 이내이면 하나의 재생 지점으로 합칩니다.
- 묶음에서 시간상 첫 사진 1장만 대표로 표시합니다. 다른 여행, 시간 조건을 벗어난 방문, 다른 지점을 거친 재방문은 별도 지점으로 남깁니다.
- 근접 사진을 묶은 다음 최대 5개의 시간순 하이라이트를 선택합니다. 원본 전체 사진 수와 여행 통계는 유지합니다.
- 직선 이동은 구간당 0.5초, 도착 후 정지는 0.3초입니다. 한 지점만 남으면 이동 구간을 만들지 않습니다.
- 다음 사진은 이동선이 해당 좌표에 도착한 뒤 표시합니다. 영상 길이는 선택된 재생 지점 수에 따라 달라집니다.

이는 촬영 좌표를 연결한 경로이며 실제 도로 이동 경로나 정확한 방문 장소 판별 결과가 아닙니다. 대표 사진도 시각적 품질이나 AI 점수로 고르지 않습니다.

## 환경 설정

`.env.example`의 공개 프런트엔드 설정을 사용합니다.

- `VITE_GA_MEASUREMENT_ID`: GA4 측정 ID. 명시하지 않으면 전송하지 않습니다. 운영 도메인 외에서는 `VITE_GA_CAPTURE_LOCAL=true`를 별도로 지정한 QA만 허용합니다. QA는 `VITE_GA_DEBUG=true`, `?internal=1`로 구분하고 운영 빌드에 QA 플래그를 넣지 않습니다.
- 현재 이벤트·GA4 보고서 명세는 [공통 측정 계획](../ANALYTICS_MEASUREMENT_PLAN.md)을 따릅니다. `journey_source`로 샘플과 내 사진을 분리하고, 스토어 이동은 랜딩과 공통인 `download_click`입니다. 내부 랜딩 링크에 유입 UTM을 다시 붙이지 않습니다.
- `VITE_CAMPAIGN_VERSION`: 캠페인 이벤트 버전입니다.
- 내부 QA는 `?internal=1`로 접속해 이벤트를 구분하고 `?internal=0`으로 해제할 수 있습니다. 이 표시는 인증 수단이 아닙니다.

앱 설치 및 소개 페이지 링크는 `src/campaignConfig.js`에서 관리합니다. `VITE_*` 값은 브라우저에 공개되므로 비밀키를 넣으면 안 됩니다.

## 배포 산출물 및 한계

- 운영 주소는 `https://map-mory.com/recap/`이고 기존 랜딩은 `/`에 유지합니다. 운영 빌드 `dist/recap`의 내용을 랜딩 CodeDeploy 묶음의 `client/recap/`에 배치합니다. 캠페인 파일로 랜딩의 `client/index.html`이나 `client/assets/`를 덮어쓰지 않습니다.
- 운영 빌드는 Vite `base=/recap/`를 사용합니다. JavaScript/CSS/폰트뿐 아니라 런타임에서 지정하는 팀 샘플 사진도 해당 경로를 사용합니다. 기존 루트/Sites용 `dist/client`는 별도로 유지하며 운영 `recap/` 폴더에 잘못 복사하지 않습니다.
- `.openai/hosting.json`, `worker/index.js`, `scripts/prepare-sites-build.mjs`는 기존 Sites 호환 빌드 계약을 유지합니다. EC2 정적 서빙에 Node 서버나 Worker 실행은 필요하지 않습니다.
- 사용자가 준비한 랜딩 CodePipeline → CodeBuild → 수동 승인 → CodeDeploy 흐름을 재사용합니다. 캠페인 설치·빌드·테스트와 위 정적 파일 병합이 끝난 하나의 묶음을 승인·배포하도록 연결해야 합니다. 배포용 `landing-release`에는 캠페인 소스와 연결 변경이 모두 포함되어야 하며, `main` 대상 기능 PR만으로 자동 배포되지는 않습니다.
- 기존 `landing/scripts/deploy-ec2.sh`는 메인 랜딩 전체를 교체하므로 캠페인만 담아 실행하지 않습니다. 새 DNS/인증서나 별도 개발 서버 포트는 필요하지 않습니다. Nginx의 기존 `root`와 다른 location을 확인한 뒤 `/recap` 리다이렉트, `/recap/`의 앱 HTML fallback, 누락된 정적 자산의 404 응답을 별도 설정합니다. 이 PR은 운영 Nginx나 AWS 리소스를 변경하지 않습니다.
- 사진 앱에 위치가 보이더라도 브라우저에 전달된 파일에서 메타데이터가 제거됐을 수 있습니다. HTTPS나 현재 위치 권한으로 과거 촬영 좌표를 복원하지 않습니다.
- 영상 저장은 브라우저의 `MediaRecorder` 및 Canvas 캡처 지원에 따라 MP4 또는 WebM을 사용합니다. 지원되지 않는 환경에는 PNG 저장 경로가 있습니다.
- 대량 사진 분석과 영상 생성은 기기의 메모리·성능 영향을 받습니다. 사진 자동 품질 평가, 서버 렌더링, 앱으로의 기록 가져오기는 구현 범위가 아닙니다.
- 초기 보호 한도는 선택 파일 200개, 총 500MiB, 파일당 50MiB이며 화면에서는 MB로 안내합니다. 한도 초과 시 메타데이터를 읽기 전에 전체 선택을 거절하고 안내하므로 사진을 조용히 누락하지 않습니다. 허용된 사진은 3장씩 처리하고 배치 사이에 브라우저에 제어를 반환합니다. 이는 모든 기기에서 메모리 부족을 방지한다는 보장은 아니며 실제 기기 검증에 따라 조정할 수 있습니다.

로컬 디자인 캡처, `node_modules`, `dist`, 실제 환경 파일은 Git에 포함하지 않습니다.
